Local folder storage mode: phases and file plan

Part of the design in ../local_folder_mode.md (section 9). Same conventions: repo-root-relative paths, line counts and file:line at HEAD 48988a20 (VERSION 0.1.199). Section numbers are global: 2.8 to 2.10 and 7 are in modes_and_migration.md, 3.4 to 3.8 in storage_rules.md, 4 in feature_matrix.md, 6 in security_and_tabs.md, 8 in testing.md, 11 in unverified_and_sources.md, and 12 in revision_log.md. Sizes are estimates.

9.1 Phases

Each phase is one or more normal rounds: VERSION bump, docs/versions/<v>.md plus its docs/SUMMARY.md entry, and the docs/LLM_CHECK.md round log (docs/AGENTS.md, round-end convention).

An app's wiring lands in the phase that ships its sign-in option: its local_folder startup step, prepare: LocalFolderBoot.preload in main.dart, the controller and StorageModeClient default client in _NotechondriaAppState with the NotechondriaApp(localFolder:) test seam, the settings gating (including onPing and the GitHub card gate), and its app-level smoke checks. An app without that wiring ignores the shared mode key (main 2.10 rule 1), so it never calls a folder route that does not exist yet. Within a wired app, every control whose route arrives in a later phase or is cloud-only is gated with cloudOnly(...) (cloudOnlyAction(...) for a required action callback), the shared session mixin's helpers; the GitHub card is gated until Phase 5 (9.3), and F18's template restore stays gated (T7(f)). Both gates were placed in Phase 1 and stay inert until an app's localFolder is set (12.4). The editor gets its option at the end of Phase 2, the planner and portal at the end of Phase 3. Until an app's option ships, nothing can write the key for it, so no feature flag is needed (AGENTS.md 1.2).
