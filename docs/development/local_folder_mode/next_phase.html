Local folder storage mode: next phase and session handoff

Handoff written 2026-10-20 at VERSION 0.1.202 (code at 5efd96ff), so that a new agent session on a new machine can continue from GitHub alone. Part of the design in ../local_folder_mode.md. Paths are repo-root-relative; lf/ is short for frontend/notechondria_shared/lib/src/local_folder/. Line counts were taken at 5efd96ff; run wc -l again before relying on them.

Where things stand

  • Repo github.com/Trance-0/Notechondria, branch main. CI (backend-tests, frontend-pages, docs-pages) is green at 0.1.202. GitHub Pages serves 0.1.202 for the editor, planner, and portal, and the backend handshake reports 0.1.202.
  • Done (implementation_plan.md 9.1): Phase 1, the foundation, in 0.1.200 with the option hidden; Phase 2 in 0.1.201, where the editor shows "Use a local folder (no account)"; Phase 3 in 0.1.202, where the planner and portal show it too.
  • Folder mode runs on desktop Chrome and Edge over https or http://127.0.0.1; Firefox, Safari, mobile, and plain http show the option disabled with the reason.
    • Editor: notes, courses, trash with the empty-trash cascade, attachments, covers, avatar, history and snapshots, study sessions, search (the note_search_score port), front page, heatmap, settings.
    • Planner: the note and course routes, plus events with recurrence, deadlines, the week view, and calendar feeds (.ics import; URL subscribe with the CORS fallback message). At connect it pushes browser-local courses, events, and feeds into the folder with the client_local_id upsert.
    • Portal: front page, notes, courses, planner events, and the same connect-time push. Each route shell starts the folder session itself (design review 3 T1), so a cold #/note/<uuid> opens the folder first.
  • Not done: Phases 4 and 5 (sections B and C below); the open findings and deferred items in deferred.md, ending with "Deferred from the 0.1.202 final review" (N1 to N15); U1, U5, U7, U10, U17, and U18 (unverified_and_sources.md 11.1), which need real desktop Chrome; and the 17 manual checks of testing.md 8.6 with a real disk folder, which no agent has run and the owner should. Code-versus-design differences are in revision_log.md 12.4 to 12.6; Phase 3 has no entry yet.
  • Not on GitHub: the agent reports in .agents/tasks/ (design reviews 1 to 3, phase reviews, progress notes), excluded through .git/info/exclude, and the run logs under /tmp/nc_verify/. Their findings are summarized in deferred.md and revision_log.md; design doc references to those paths name files a new machine will not have.

How to resume on a new machine

  1. Clone and initialize the submodule. The root AGENTS.md is a submodule directory (rules in AGENTS.md/AGENTS.md), empty until initialized:

    git clone git@github.com:Trance-0/Notechondria.git
cd Notechondria
git submodule update --init

  2. Read AGENTS.md/AGENTS.md (1.6 has the 1000-line cap, 1.8 the message shape), docs/AGENTS.md (host budget, no local containers under 16 GB RAM, round-end convention, module and process names), frontend/AGENTS.md, docs/development/local_folder_mode.md with the part files the step needs, deferred.md, and this file.

  3. Check the host before any build: free -h, nproc, docker ps. Flutter containers need at least 16 GB RAM. Take at most 70% of the free RAM, run one heavy container at a time, and wrap every run in timeout. On a smaller host, run static checks only and let CI prove the rest after the push.

  4. No host Flutter SDK is needed; everything ran in Docker (ghcr.io/cirruslabs/flutter:stable, Flutter 3.44.0). Build the Chromium image with scripts/local_folder_verify/build_image.sh, run scripts/local_folder_verify/ci.sh, and compare with the baselines below. scripts/local_folder_verify/README.md describes the scripts.

  5. Push over SSH, git push git@github.com:Trance-0/Notechondria.git main:main (the last machine had no HTTPS token), or over HTTPS with a token from a credential helper, never in a remote URL or a tracked file. Then run the "After pushing" checks of docs/AGENTS.md: CI conclusions, the backend handshake, and each bundle's version.

Working method that worked

  • Ownership. Parallel agents split work by directory: the shared lf/**, each app's frontend/<app>/, and the shared UI (frontend/notechondria_shared/lib/src/components/, the ARB files).
  • Locks. flock /tmp/nc_verify/flutter.lock around every Flutter container, so one heavy job ran at a time, and flock /tmp/nc_verify/git.lock sh -c 'git add <files> && git commit ...' for commits, staging files by name, never git add -A.
  • Scratch copies. Tests ran on git archive HEAD frontend unpacked into a scratch directory, never on the working tree. Containers had no -p mapping; browser runs used --network none (the OPFS unit tests need the network for pub get). On the last host --memory was not enforced and --cpus failed, so timeout was the real bound.
  • Reviews. Larger sub-steps had their own review (Phase 1a, Phase 1b, loop 2a). Each phase ended with a read-only final review (the reviewer edits nothing), then the release step (VERSION bump, docs/versions/<v>.md with its docs/SUMMARY.md entry in the same commit, the docs/LLM_CHECK.md round log), then the blocking fixes, then the push.
  • Records. Code-versus-design differences go to revision_log.md and deferrals to deferred.md, in the same commit as the code.
  • Push after tests pass, then confirm CI and the deployed bundles. Docs-only commits skip the VERSION bump (docs/AGENTS.md).
  • l10n. flutter gen-l10n still rejects activityWeightN; the workaround is in deferred.md ("Deferred from Phase 2").
