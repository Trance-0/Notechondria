Part of the design in ../local_folder_mode.md. The phase checklist (Phases 1 to 5, Q13, and the manual desktop Chrome checks) is in docs/TODO.md under "Local folder storage mode". These lists moved here from that section in 0.1.202 to keep docs/TODO.md under the 1000-line cap (AGENTS.md 1.6); the bullets are unchanged. "Above" and "below" in them refer to this file, and "## Planner" to docs/TODO.md.

Review follow-ups, open items, and deferred lists

  • Phase 0 spike, U3 (Phase 2): a real click on the Flutter "Use a local folder" button keeps transient activation until showDirectoryPicker, on both the semantics and the pointer path, in headless Chromium 131 (unverified_and_sources.md 11.1). The other spike items are on the manual list under "Deferred from Phase 2".
  • Phase 1b review follow-ups (.agents/tasks/phase1b-review.json), landed before Phase 2 shows the option (design revision_log.md 12.5):
    • P1B-1 (MEDIUM): note and course lookups read every note inside the lock. Lookups now go through the in-memory index (schema 2 holds the note summary fields) and re-read only the note served or rewritten. Chromium timing over 2,000 OPFS notes (test/local_folder_opfs_timing_test.dart): single-note GET 27 ms, PATCH 59 ms; 0.1.200 answered the same GET with a 503 after 8 s.
    • P1B-2: "Check for updates" no longer counts a locally answered handshake (x-notechondria-backend: local-folder) as a cloud answer.
    • P1B-3: after a failed roll-forward, write lookups skip nothing, so a PATCH, DELETE, or draft upsert of the pending note answers writeBlockedByJournal.
    • P1B-4: scrubRouteDetail on every 404 and 501 detail in LocalFolderTransport._detail.
    • P1B-5: tests for the inert folder branches, a throwing prepare, the 7 s write start, and the transport R3 path.
    • P1A-7 (LOW): closed in 0.1.200; the invalid to\u212Aen test added, and overlapping sentinels are now broken too.
  • Loop 2a review follow-ups (.agents/tasks/review-2a.json, design revision_log.md 12.5; review-2a-pass2.json APPROVED and marks L2A-1 to L2A-5 and L2A-7 fixed, with the residues listed below):
    • L2A-1 (MEDIUM): index.json was written only by scans and trusted on open, so a reload listed pre-edit rows. The in-memory index is now flushed to index.json 1 s after this tab's first write of a burst, and stored note entries are compared with the disk by the first listing that meets them.
    • L2A-2: a rescan keeps the index changes this tab made while it ran.
    • L2A-3: a re-read note whose sidecar differs from its entry gets a fresh entry (another tab's description edit, a renumbered id).
    • L2A-4: note delete picks comments by source_note_uuid and checks is_public on disk.
    • L2A-5: course delete stats every note body before it selects by course_slug.
    • L2A-7: the Chromium timing test asserts every route's hold.
  • Search hold: Phase 1's substring search read every body its title and description missed, in batches of 32, and held the shared lock 1.2 to 1.3 s over 2,000 OPFS notes in headless Chromium. The Phase 2 note_search_score port reads every body (each score needs the content) and was not timed in Chromium. Bound it (body cache, or chunked holds within the 8 s read deadline).
  • Scan page size: a 500-entry page of the first full scan held the lock 1,993 ms, then 2,087 ms and 2,228 ms in later runs over the same 2,000 OPFS notes, above R4's 2 s target. Use a time-bounded page before folders of that size are common (the timing test only prints this number).
  • L2A-6, Phase 4: the first list after an open from index.json stats every stored note entry in one hold (1,733 ms for 2,000 notes), and a listing that finds many new files reads them in one hold (626 ms for 300). About 2,300 stored notes or 900 new files pass the 2 s target. Bound both per hold and leave the rest to Phase 4's paged rescans and change path.
  • Other tabs' and outside programs' edits to an existing note made after this tab compared it reach this tab's lists at its next rescan, or when this tab reads that note, until Phase 4's change messages. A note another tab's identity fix renumbered answers 404 by its new id until its old id is asked for or a rescan runs. Course delete stats every note before its detach chunks, so a note moved into the course between that pass and its chunk keeps the slug.
  • Deferred from Phase 2 (shared content routes; design revision_log.md 12.6):

    • Editor wiring: on desktop Chrome, check the spike items U1, U5, U7, U10, U17, and U18 (unverified_and_sources.md 11.1) with the manual checks of testing.md 8.6; headless Chromium answers the picker with AbortError, so the real dialog (check 2) is still unchecked.
