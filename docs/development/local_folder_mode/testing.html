Notechondria Documentation

Local folder storage mode: testing strategy

Part of the design in ../local_folder_mode.md (section 8). Same conventions: repo-root-relative paths, file:line at HEAD 48988a20 (VERSION 0.1.199), and section numbers that refer to the main document unless they start with 8. Sections 2.8 to 2.10 and 7 are in modes_and_migration.md, 3.4 to 3.8 in storage_rules.md, and 6 in security_and_tabs.md.

8.1 Layers

  1. Unit tests in frontend/notechondria_shared/test/local_folder/: codecs, router, journal crash and roll-forward tests including the replay external-edit check (3.4.1), two-transport concurrency tests (6.2), ID allocation and duplicate identities (3.7), trash semantics and the empty-trash cascade (3.5), course delete over notes, trashed notes, events, and feeds (3.5), snapshot pools (3.8), scans of hand-edited files with wrong-typed fields (3.8), recurrence and search ports, archive bridge, the secret denylist in both directions (5), the per-device settings filter (F08), the detail-sentinel check (2.5), decideStorageMode over seeded SharedPreferences (2.8), the opening hold and the deadlines (2.9), and the StorageModeClient routing table (2.8). T6 (design review 3) is resolved by a CI step: .github/workflows/frontend-pages.yml runs flutter test test/local_folder/ -r compact from frontend/notechondria_shared ("Test notechondria_shared local folder", after the three app builds, in the job that already installs Flutter), so the journal, concurrency, identity, denylist, and storage-mode tests gate every Pages deploy. The step relies on flutter test resolving packages: an explicit flutter pub get in that package exits 1 on its l10n generation with Flutter 3.44 ("Placeholders used in selects must be of type 'String'"). The rest of the shared package's tests stay out of CI.
  2. Per-app smoke tests (CI), 8.5.
  3. OPFS and Web Locks integration tests in Chromium (8.3), run in a Docker container with the Flutter SDK and Playwright's Chromium, on a host with at least 16 GB RAM, and not in GitHub CI unless the owner adds a job (Q13). They cover what only a browser can show: that the locks.request wrapper keeps the lock for the whole operation (2.5), and that a throwing void listener reaches the zone's error handler.
  4. Manual checks on desktop Chrome (8.6).

8.2 Dart-side fake

MemoryFolderFs implements FolderFs, with injectable failures (NotAllowedError, NotFoundError, abort mid-write, external edit with a new lastModified), revoke() and grant() to simulate a lost and restored permission, and crash points ("throw after the n-th write"). MemoryFolderLocks is the matching Web Locks double, with shared and exclusive modes and abort timeouts, shared by several transports, and a change channel double that can delay or drop messages. MemoryHandleStore holds remembered handles, and MemoryFolderPicker returns a preset MemoryFolderFs root or throws AbortError, standing in for "Choose '' again". MemoryFolderPlatform bundles these for LocalFolderController.forTest(app:, boot:, platform:), which is what smoke tests pass as NotechondriaApp(localFolder: ...) (2.7). They are exported from a separate library, package:notechondria_shared/local_folder_testing.dart, so production code never imports them. The fake sits at the FolderFs level because package:web types are extension types and cannot be mocked by implementing them (dart.dev package:web page). MemoryFolderLocks keeps a lock for as long as the Dart operation runs, so it cannot show the JavaScript return-value bug of 2.5; 8.3 covers that in Chromium.

8.3 OPFS stand-in and Web Locks tests in Chromium

  • The test file is frontend/notechondria_shared/test/local_folder_opfs_test.dart. It lands in Phase 1 with the web FolderFs and the lock wrapper, gains attachment-byte tests in Phase 2 and archive-bridge tests in Phase 4, and runs from frontend/notechondria_shared.

  • const bool kLocalFolderOpfsTestHook = bool.fromEnvironment('NOTECHONDRIA_TEST_OPFS_FOLDER'); defaults to false. Only when it is true does the web FolderFs take its root from navigator.storage.getDirectory() (a per-test subdirectory) and report permissions as granted. Run with flutter test --platform chrome --dart-define=NOTECHONDRIA_TEST_OPFS_FOLDER=true test/local_folder_opfs_test.dart.

  • Lock tests, over the real navigator.locks and the production folder_lock_web.dart wrapper:

    • two overlapping exclusive requests on one name, the first awaiting several timers (about 200 ms in total) before it returns: the second starts only after the first returns, and navigator.locks.query() taken during the first lists one held and one pending request;
    • an operation that throws: the caller receives the error, and a following request on the same name is granted at once, with nothing left in query().held;
    • two shared holds overlap, and an exclusive request waits for both;
    • a lock wait longer than its AbortSignal.timeout (shortened for the test) fails with the folder-lock message (6.2 R5);
    • a throwing BroadcastChannel listener reaches the zone's error handler.

    Checked in Phase 1a by swapping in a guarded (void) wrapper in a scratch copy: the first, third, and fourth tests fail (the lock is released before the operation's first await), so they are the regression test for 2.5. The second passes either way, because a guarded wrapper releases the lock even earlier.

  • Where it runs: in a Docker container with the Flutter SDK (the version CI pins) and Playwright's Chromium, with CHROME_EXECUTABLE pointing at that Chromium. docs/AGENTS.md allows Flutter containers only on hosts with at least 16 GB RAM, so the run follows its host resource budget: measure free -h and nproc first, cap the container (docker run --rm --memory=6g --cpus=2 ...), wrap the test in timeout 1200, run one container at a time, and kill it after 5 minutes without output. Fallback if it runs out of memory or hangs: run only the VM tests and the manual checks in 8.6, and say so in the round summary. GitHub CI does not run these tests unless the owner adds a Chrome job (Q13).

  • Working recipe (Phase 1a, Flutter 3.44.0, Chromium 131): a derived image FROM mcr.microsoft.com/playwright/python:v1.49.1-noble with COPY --from=ghcr.io/cirruslabs/flutter:stable /sdks/flutter /sdks/flutter, apt-get install unzip xz-utils, flutter precache --web at build time, and CHROME_EXECUTABLE set to a two-line wrapper that runs /ms-playwright/chromium-1148/chrome-linux/chrome --no-sandbox "$@" (the container runs as root). The repo is copied to a scratch directory and mounted there, never read-write. Run, with no -p mapping: docker run --rm --memory 6g -v <scratch>:/work ... flutter test --platform chrome --dart-define=NOTECHONDRIA_TEST_OPFS_FOLDER=true test/local_folder_opfs_test.dart. The network stays on because the web test runner runs pub get for flutter_tools; with --network none it stops with "Failed to update packages". Sampling /proc/net/tcp during the run showed only 127.0.0.1 listeners (the test server and Chrome's DevTools port). On this host docker run --cpus fails (cgroup v2 in threaded mode) and --memory is accepted but not enforced ("Limitation discarded"), so the bound is the timeout wrapper and one container at a time. Result: 7 of 7 passed; the whole container run took about 25 s.

  • Timing check (phase 1b review P1B-1, 12.5): test/local_folder_opfs_timing_test.dart seeds 2,000 notes on OPFS, opens the folder with the real Web Locks wrapper, and times each route through the transport, reading the lock holds from onHold. It fails when any timed step holds the lock for 2 s or more (kFolderLockHoldTarget, 6.2 R4): the single-note GET and PATCH by id and UUID, the first list after the open from index.json (which stats every stored entry), the note page, all notes, search, courses, the draft upsert, note delete, the index.json flush, course delete (which stats every note body), and a page with 300 notes the index lacks. The single-note routes must also answer within 2 s. Only printed, not checked: the seed time, the first open's full scan and its longest hold, and the open from index.json. It runs in the same container command, after the OPFS test file. 0.1.200's full reads answered a single-note GET with the 8 s read deadline's 503 (hold 11 s); the numbers after the change are in 12.5.

  • Unreachable in production: the flag is a compile-time constant, and the release builds pass only APP_VERSION (.github/workflows/frontend-pages.yml:63,73,83, .github/workflows/portal-release.yml:134-156), so the compiler drops the branch. An optional CI guard greps each built main.dart.js for the hook's marker string (Q13).

  • How OPFS handles answer queryPermission is unverified (U10); the hook does not depend on it.

8.4 Contract fixtures (drift control)

One sanitized backend response per (a) and (b) route lives in frontend/notechondria_shared/test/fixtures/api_v1/, and a unit test asserts that the local router returns the same keys and JSON types for the same request.

  • Phase 1 fixtures are hand-written. No host available to this work can run the backend: docs/AGENTS.md bans local containers below 16 GB RAM, and the host Python is 3.14 against 3.11-era pins. Each fixture is built from the serializer or payload helper that renders its route: backend/notes/api.py (NoteSummarySerializer :344, NoteDetailSerializer :423, CourseSerializer :450, NoteVersionSerializer :573, CalendarFeedSerializer :631), backend/creators/api.py (the settings representation at :395-428), and the payload helpers in backend/notes/services.py (for example note_session_payload :367). Each one is checked against the assertions in backend/notes/tests.py and backend/creators/tests.py. A _source key names the serializer and the backend test it was checked against; the comparison ignores keys that start with _.
  • Q14's backend test is the CI recorder. backend/notes/test_api_contract.py runs in backend-tests.yml (python manage.py test). It seeds one creator's data, calls each fixture's route with the Django test client, and fails when a key or JSON type differs from the committed fixture. It also writes every live response under backend/build/contract_responses/, which an actions/upload-artifact step publishes, so a fixture can be refreshed from CI without a local backend. The fixture directory joins the workflow's paths: filter (.github/workflows/backend-tests.yml:16-19), so a fixture-only change runs the test.
  • Format (0.1.200). Each file holds _source, _setup (empty, course_and_note, or trashed_note, seeded the same way through the API on both sides), request (method, path, optional body, with {course_id}, {note_id}, and {note_uuid} replaced by the seeded ids), status, and body. _folder_omits lists dotted key paths the folder leaves out on purpose (the per-device settings of F08, also inside app_settings), and _backend_route: false marks the two routes below. Null on either side is compatible, and list elements are compared when both lists are non-empty. The Dart side is test/local_folder/fixtures_contract_test.dart. Phase 1 has 21 fixtures; Q14's test passed against all 19 backend routes in a python:3.11-slim container before the first push (12.4).
  • Routes the backend does not have (GET /auth/session/, POST /auth/logout/, Q17) get no recorder. Their shapes come from the client code that parses them. _restoreSession reads authenticated and passes the whole map to applyAuthPayload (editor core/auth_flows.dart:174-177, portal core/bootstrap.dart:325-328), which reads token and user (app_shell_session_mixin.dart:181-182). The session fixture is therefore {"authenticated": true, "token": "<the request's token>", "user": {<the GET /settings/ profile keys>, "is_local_folder": true}}. Logout's response is decoded and discarded (editor core/http_client.dart:695-704), so its fixture is {}.

8.5 Smoke-test checks

CI runs only test/smoke_test.dart per app (.github/workflows/frontend-pages.yml:59,69,79). Each app adds test/local_folder_smoke.dart with registerLocalFolderSmokeTests(), called from smoke_test.dart's main, so the CI file grows by two lines (planner's is already 767 lines).

  • Harness. Each folder-mode check boots NotechondriaApp(localFolder: LocalFolderController.forTest(...)) over MemoryFolderPlatform (8.2) with no client, so the production default-client line runs (2.7). The whole test body, including pumpWidget and every pump, runs inside http.runWithClient(body, () => recorder) (package:http 1.6.0 client.dart:228). recorder is a BaseClient that records every request and fails the test on any request outside the passthrough check below. The precedence check, which starts in cloud mode on purpose, uses the smoke tests' existing fake backend (MockClient(backend.handle)) as the zone client instead. Client() returns the zone's client first (client.dart:42), so the recorder is what StorageModeClient's inner client, a multipart request.send() (base_request.dart:141), and a top-level http.get (http.dart:168) all receive: a missed multipart site or a stray http.* call fails the test instead of escaping it. package:http warns that Flutter does not guarantee which zone runs a callback (client.dart:219-226), so setUp also sets HttpOverrides.global to an override whose createHttpClient fails the test (restored in tearDown); a dart:io client created outside the zone fails too.
