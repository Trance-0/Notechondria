# 0.1.185 - Course loading: 16s → sub-second (storage N+1 + lazy pages)

## Measured baseline (prod, before)

| Endpoint | Time | Size |
| --- | --- | --- |
| `courses/22/notes/` | **16.2 s** | 317 KB |
| `courses/` | 1.8 s | 22 KB |
| `front-page/` | 2.6 s | 94 KB |

## Root cause

The per-row author payload called `ensure_creator_avatar` →
`storage.exists()` — an **R2 network HEAD per note row** (0.1.184's
`mirrored_avatar_is_fresh` added a second) — ~2 × 193 storage round-trips
per request for the *same single author*. `courses/<id>/notes/` also had
no pagination at all (the `limit` param it appeared to accept belonged to
a different view).

## Fixes

Backend:
- `creator_summary_payload` performance contract: **zero storage/network
  I/O, zero writes** — pure field reads; `mirrored_avatar_is_fresh` is
  field-only (`avatar_mirrored_from` is only written after a successful
  save, so the comparison is trustworthy). Payload memoized per request
  by creator id (list rows overwhelmingly share authors). This also
  speeds `courses/` and `front-page/` (their `recent_notes`).
- `courses/<id>/notes/` pagination: `?limit=&offset=` → `{results,
  total, offset, limit, has_more}`; bare list preserved without `limit`
  (legacy clients unaffected).

Portal:
- Open-course critical path = `openCourse` + **first 10 notes** in
  parallel; the full course-list refresh moved off-path (background).
- Course view shows a **loading bar** until real data arrives — the
  stale `recent_notes`/empty-state placeholders that used to render
  before content are gone.
- **Infinite scroll** streams further pages (20/page) near the bottom;
  bottom progress bar while streaming; no manual buttons.

## Verification

`CourseNotesPerformanceTests`: bare-list compatibility, pagination
envelope both pages, **author payload does no storage I/O** (patched
`creator_has_image_file` raises if touched), and per-request author
memoization (25 rows → 1 computation). Post-deploy prod timings recorded
in the round summary (target: module list + note list < 500 ms).

## Measured after deploy (prod, 3 runs)

| Endpoint | Before | After (warm) |
| --- | --- | --- |
| `courses/22/notes/?limit=10` | n/a (param ignored) | **0.21–0.60 s** |
| `courses/22/notes/?limit=20&offset=100` | n/a | **0.21–0.48 s** |
| `courses/22/notes/` (full 193, legacy) | 16.2 s | **0.77 s** (21×) |
| `courses/` | 1.8 s | 0.33–0.60 s |
| `front-page/` | 2.6 s | 0.57–0.77 s |

First hit after deploy was 2.1 s (cold worker); warm averages for the
course module/note lists are comfortably **< 500 ms**. Full suite (245
tests) verified in the Docker harness before push; backend CI green
(the two prior red runs were AvatarMirrorTests asserting a filename the
`upload_to` callable rewrites — fixed to assert storage location).
