# 0.1.146 - MCP Phase 3: full CLI tool parity (41/41) + the one API gap

## User request

Continue through `docs/TODO.md`. MCP migration **Phase 3**: port the
remaining tools from `backend/mcp/tools.py` into the standalone CLI
(`cli/notechondria_mcp/tools.py`) so it reaches full parity, with
matching input schemas.

## The one gap (belated Phase 1 fix)

The Phase 1 audit (0.1.145) claimed full `/api/v1/` coverage, but
porting `list_note_sessions` surfaced a miss: `NoteSessionListCreateApiView`
was **POST-only** — there was no REST `GET` to list sessions. Added one
to `backend/notes/api.py`, mirroring the MCP tool: filter by
`?note_id=`, cap `?limit=` (default 50, max 200), newest `started_at`
first, returns a bare list of `note_session_payload`. Covered by a new
`notes/tests.py` test (`test_note_session_list_get`: lists all, asserts
newest-first ordering, and the `note_id` filter). Every other tool
already had a REST endpoint.

## CLI parity (30 tools added → 41 total)

`cli/notechondria_mcp/tools.py` went from the 11-tool starter subset to
all **41** tools, each mapping to `/api/v1/` via the `requests` client
with the same `Bearer ntc_<key>` auth. Added:

- **Profile**: `update_profile`.
- **Notes**: `get_note_by_uuid`, `search_notes`.
- **Note versions**: `list_note_versions`, `snapshot_note`,
  `restore_note_version`.
- **Attachments**: `list_attachments`, `delete_attachment`.
- **Recycle bin**: `list_deleted_notes`, `restore_deleted_note`,
  `empty_recycle_bin`.
- **Courses**: `update_course`, `delete_course`, `list_course_notes`,
  `reorder_courses`, `subscribe_course`, `unsubscribe_course`.
- **Activity / heatmap**: `get_heatmap`, `get_recent_activity`,
  `get_activity`, `get_activity_week`.
- **Planner events**: `update_event`, `delete_event`.
- **Note sessions**: `list_note_sessions`, `create_note_session`,
  `end_note_session`.
- **Calendar feeds**: `list_calendar_feeds`, `create_calendar_feed`,
  `update_calendar_feed`, `delete_calendar_feed`.

Notable mapping details:
- `unsubscribe_course` → `DELETE courses/<id>/subscribe/` (the same view
  that handles subscribe via `POST`).
- `empty_recycle_bin` → `DELETE notes/deleted/empty/`.
- `end_note_session`: the REST `PATCH` only sets `ended_at` when
  supplied (the in-backend tool stamps "now" server-side), so the CLI
  defaults `ended_at` to the current UTC time when the caller omits it.
- `get_activity` honors its `limit` client-side (the REST `activity/`
  endpoint always returns the top 10).
