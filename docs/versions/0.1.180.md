# 0.1.180 - Startup image, keep-offline login merge, course edit entry, starter cleanup

Four owner asks in one round, shipped in two CI-validated commits.

## Course dropdown + edit entry (bug fix)

- **Planner activity view had no course filter** (0.1.169 added it to the
  portal only) — ported `_CourseFilterBar` (stateful `_ActivityPage`,
  per-course day/deadline filtering).
- **Settings button right of the filter** (both apps): disabled with a
  tooltip on "All courses"; on a specific course it opens the new
  **course-edit dialog** — title, description, calendar colour hue
  (hue-only slider + theme-default checkbox + live swatch). Saves via new
  `client.updateCourse` (PATCH `/courses/<id>/`, `color_hue` writable
  since 0.1.178) and refreshes so the hue paints immediately.
- **Portal course detail**: owner-only "Edit course" button beside
  subscribe/unsubscribe.

## Stale template cleanup

The front-page "recent public courses" carousel listed **every** course
row, leaking stale personal buckets (the pre-0.1.120 editor "Inbox") onto
everyone's front page. It now only surfaces courses with ≥1 public note
(`FrontPageCarouselTests`). Starters already seed exactly one welcome
note (backend + editor draft) and no subscriptions. The old prod "Inbox"
course row itself belongs to the admin account and can be deleted in-app;
it no longer appears anywhere public.

## Custom startup image (portal Preferences)

Preferences → **Startup image**: remote URL or local upload (≤50 MB,
stored in `LocalAttachmentStore` under `local://app-splash/…`; shared
per-file cap raised 20→50 MB), plus reset-to-default. When set, boot
shows `_CustomSplashOverlay` — the image **spans the screen at a fixed
x-y ratio** (`BoxFit.cover`) with title/version/status on a bottom scrim,
tap-to-skip, auto-dismiss; default remains the reactor `SplashScreen`.

## Keep offline data after login

Checkbox under the sign-in card (default **on**), persisted as
`keep_offline_data_on_login`. After a fresh OAuth sign-in:
- **kept** → background `_pullCloudNotesToLocal()` merges cloud→local;
  every local save already carries a `last_edit` timestamp and the pull's
  existing **conflict dialog prompts the user to pick which version to
  keep** when both sides changed;
- **unchecked** → local drafts are cleared so a shared machine never
  leaks the previous user's offline notes into the new account.

## Verification

Backend: `FrontPageCarouselTests` (public-note filter + default course);

Dart gate for portal + planner + shared (50 MB cap).
