## Context

The owner asked to (a) verify repo progress, (b) plan the remaining
portal-app completion work with the fewest owner-attention rounds, and
(c) enable agents to test the app remotely (Docker full stack + MCP)
instead of the owner running builds and reading logs.

## What changed

### Docker frontend image builds repaired (broken since 6a62288c)

Root cause: the `notechondria_shared` extraction (2026-04-15) made all
three apps depend on `path: ../notechondria_shared`, but the frontend
Dockerfiles / compose files kept the **app directory** as the build
context, so `flutter pub get` inside the image could never resolve the
shared package. No Dockerfile or compose change had landed since
2026-04-09 — every frontend image build failed from that point on.

- `frontend/{editor,planner,portal}_app/Dockerfile`: build context is
  now the parent `frontend/` directory; `notechondria_shared/` is
  copied to `/notechondria_shared` (so the relative path dep resolves
  from `/app`), app sources copied from `<app>_app/`, and the nginx
  template COPY path gained the app prefix. A header comment documents
  the required context.
- Root `docker-compose.yml`: the three frontend services build with
  `context: ./frontend` + `dockerfile: <app>_app/Dockerfile`.
- App-local `frontend/<app>/docker-compose.yml`: `context: ..` +
  `dockerfile: <app>_app/Dockerfile`.
- The pre-existing `frontend/.dockerignore` already covered the wider
  context (excludes `build`, `.dart_tool`, `windows`, …).
