# 0.1.193 - Course ownership transfer

Fixes #11 — the last remaining piece of the #8 course-metadata modal
(title / description / colour hue / cover / bound-repo editing shipped in
0.1.180). Owners can now hand a course to another creator.

## Backend

- **`POST /api/v1/courses/<id>/transfer/`** (`CourseTransferApiView`,
  owner-only). Body: `{"target": "<username or email>"}` (also accepts
  `username` / `email`). Case-insensitive lookup.
  - 403 if the requester doesn't own the course, 401 if anonymous.
  - 404 if no user matches the target; 400 if the target is the current
    owner or no target was given.
  - **409** if the recipient already has a category with the same title
    (titles are case-insensitively unique per creator — mirrors the PATCH
    guard) so the owner renames first rather than creating a collision.
  - On success: reassigns `Course.creator_id`; **notes keep their own
    `creator_id`** (co-authored notes stay with their authors);
    `client_course_id` is dropped (it was the old owner's device-local id
    and would collide with the recipient's unique key); and the **GitHub
    binding is cleared** because it points at the previous owner's repo,
    which the recipient cannot push to. The response echoes
    `git_binding_cleared`. Wrapped in a transaction; audit-logged.
- Tests: `courses.tests.CourseTransferApiTests` — transfer by
  username/email (case-insensitive), notes keep their author, git binding
  cleared, non-owner 403, unknown target 404, self 400, missing target
  400, title collision 409, anonymous rejected.

## Frontend (portal + planner)

- `transferCourse(token, courseId, target)` client method
  (`POST …/transfer/`).
- A **"Transfer ownership"** section in the course-edit dialog: a
  recipient field + a confirm-guarded button. On success the course
  leaves the account, so the owned list refreshes and the selection
  clears. Owner-gated (the edit dialog only opens for owned courses).
  Reachable from every place that dialog opens — portal's course page and
  its activity filter-bar settings button, plus planner's activity filter
  bar. The editor uses inline category rename and has no such modal, so
  it is unchanged.
