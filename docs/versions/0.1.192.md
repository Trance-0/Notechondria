# 0.1.192 - Offline cache is owner-scoped (no cross-user leak)

Fixes #13. Local drafts, courses, and events live in the browser's
storage for an **origin**, which every user who signs in on that device
shares. Before this change nothing stamped an owner on that data, so on a
shared machine user B could sign in where user A had worked offline, see
A's drafts, and push them into B's cloud account — a cross-user data
leak.

## What ships

- **Ownership decision (`local_data_ownership.dart`, shared).** A pure
  `resolveLocalDataOwner({recordedOwner, currentUser})` returns
  `claimed` (no stamp yet → the current user claims the local data),
  `sameUser` (stamp matches — normal case, case/space-insensitive), or
  `foreignUser` (stamp belongs to someone else). It is a pure function so
  it can be unit-tested in CI (see below).
- **Reconcile at sign-in (`app_shell_session_mixin.dart`, shared).**
  `applyAuthPayload` now calls `_reconcileLocalDataOwner` right after the
  session persists:
  - `claimed`/`sameUser` → record `local_data_owner` and clear any
    `foreign_local_data_owner` flag.
  - `foreignUser` → set `foreign_local_data_owner` to the prior owner,
    log a warning, and show the person signing in a heads-up. The stamp
    is **not** reassigned — retagging would let the other user's cache
    sync as the new user's.
- **No auto-push of a stranger's data.** The post-login auto-sync
  (`syncAllLocalCourses` + `syncAllLocalDrafts`) is now skipped when the
  device's cache is foreign. `_reconcileLocalDataOwner` returns that flag
  so the caller can gate the push.
- **Manual sync refuses too (all 3 apps).** `_syncAllLocalData` in the
  editor, planner, and portal returns an error (and messages the user)
  when `foreign_local_data_owner` is set, so the "sync local data" button
  can't push a stranger's drafts either.
- **Escape hatch.** The warning tells the user to clear local data
  (Settings) or sign in as the prior owner to keep the offline notes.
  Clearing local data resets the stamp via `_LocalAppStore.defaultSettings`,
  so the next sign-in claims the (now empty) storage cleanly.

The ownership keys ride the existing `applyLocalAppSettings` →
`_applyLocalAppSettings` (spread-merge) → `saveSettings` (whole-map
`jsonEncode`) path, so they persist across reloads like any other local
setting.

## Verification

- **CI-run unit tests.** `portal_app/test/smoke_test.dart` (executed by
  `frontend-pages.yml`) now covers `resolveLocalDataOwner`: unrecorded →
  claimed, empty → claimed, same user (case/space-insensitive) →
  sameUser, different user → foreignUser with the prior owner preserved
  (owner **not** reassigned), and empty current user → no-op. The shared
  package's own `test/` is not CI-run and there is no local Flutter SDK,
  so the security-critical decision was pushed into a pure function a
  CI-run app test can exercise.
- Bracket-balanced and reference-checked across the shared mixin, the new
  utility, and the three `maintenance_actions.dart` guards. Verify the
  deployed bundle version after the Pages build.

Closes #13
