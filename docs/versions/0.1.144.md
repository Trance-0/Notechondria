# 0.1.144 - Storage-usage card in planner + portal

## User request

Continue through `docs/TODO.md`. Next item: wire the shared
`StorageUsageCard` (backend host, storage arch, per-bucket
decomposition, browser quota/free, low-storage suggestions) — which
landed in the editor's Local data subpage in 0.1.136 — into planner and
portal.

## What changed

Each app gathers its own synchronous inputs and feeds the shared
`StorageUsageCard` (the card itself fetches the browser quota and
renders), mirroring the editor's `_StorageUsageSection`:

### Planner (inline settings)

- `local_store.dart`: new `bucketSizes()` (drafts / categories / cache /
  recycle bin / logs / settings / stats byte sizes from
  SharedPreferences).
- `settings_helpers.dart`: new `_probeStorageArch()` — calls
  `verifyHandshake` and returns the `storage.label`.
- `client.dart`: `verifyHandshake` added to the abstract
  `NotechondriaClient` interface (was only on the concrete client);
  `HandshakeResult` gained a `storageLabel` field, populated from the
  handshake `storage` map.
- `settings.dart`: new `_hostOf` helper + `_StorageUsageSection` widget,
  rendered as its own card above the "Login and sync" section;
  `onProbeStorageArch` threaded from the app shell.

### Portal (Local data subpage)

- Same `bucketSizes()` / `_probeStorageArch()` / `verifyHandshake`
  interface + `HandshakeResult.storageLabel` changes (in
  `client_base.dart` + `client.dart`).
- `settings_pages.dart`: `_hostOf` + `_StorageUsageSection` added, placed
  at the top of the existing `_LocalDataPage`; `onProbeStorageArch`
  threaded through `_SettingsPage` from the app shell.

## Verification

- `flutter analyze` — 0 errors/new warnings across all four packages.
- `flutter test` — planner + portal suites (and editor/shared,
  unaffected) pass.
- `flutter build web` — all three apps pass.

## Notes / scope

- No backend change: the handshake already returns `storage.label`
  (added for the editor in 0.1.136); planner/portal just parse it now.
- The shared `StorageUsageCard` is still English-only (its strings
  predate the i18n work); localizing it is part of the Phase 4
  shared-widget sweep tracked in `docs/TODO.md`.
