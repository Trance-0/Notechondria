# 0.1.141 - i18n Phase 1c: navigation + home feed translated

## User request

The language switch *still* "did nothing" — the setting saved but the
UI stayed English, and "no effective debug string was produced".
Continue translation and fix the UI text errors.

## Diagnosis

The switch mechanism is **not** broken. A reproduction test
(`test/locale_switch_test.dart`) boots the editor with `locale: zh`
already persisted and confirms the live `MaterialApp` resolves the zh
locale (`Localizations.localeOf` == `zh`) and renders Chinese widgets.
The whole chain is sound: picker → `_setLocale` → `_applyLocalAppSettings`
→ `onLocaleChanged` → `_handleLocaleChanged` → `setState` →
`MaterialApp.locale`. The same `onLocaleChanged` runs at startup
(`load_local_state`), so a saved locale is applied on boot too.

The real problem was **coverage**: 0.1.140 only translated deep
settings strings, so flipping the language left the entire high-traffic
UI — the navigation and the notes feed a user stares at every session —
in English. It *looked* like nothing happened.

## Verification

- New `test/locale_switch_test.dart` (editor): a persisted `locale: zh`
  boots the app in Chinese — asserts `Localizations.localeOf == zh`,
  `settingsEditorTitle == 编辑器设置`, and the live nav renders
  `全部笔记` (not "All Notes"). This is the regression guard proving the
  switch works end-to-end at runtime.
- `flutter analyze` — 0 errors/new warnings across shared + 3 apps.
- `flutter test` — shared suite + 3 smoke tests + locale test pass.
- `flutter build web` — all three apps pass.
