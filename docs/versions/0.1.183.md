# 0.1.183 - CI fix + course dropdown in event dialogs across apps

## CI compile fix (owner's pasted failure)

0.1.182's editor avatar fix declared `avatarFallbackUrl` in the outer
card builder but used it inside `_LearnerNoteCardBody` (a separate
widget) — `frontend-pages` failed on the editor smoke test. The field +
constructor param + call-site now thread through properly.

## Course (category) dropdown in event dialogs — ALL apps

- **Portal**: the create/edit event dialogs' course dropdown (0.1.181)
  was gated on `courses.isNotEmpty` — with the session bug (fixed in
  0.1.182) the course list was empty after any reload, so the field never
  appeared. The dropdown now renders **unconditionally** with "Inbox
  (uncategorized)" as the default plus whatever courses are loaded.
- **Planner**: its create-event dialog never had the dropdown — ported:
  "Course (project)" selector (Inbox default), `courseId` threaded
  through `onCreatePlannerEvent` (page + FAB typedefs) into
  `_createPlannerEvent`'s local and cloud payloads, replacing the silent
  `_selectedCourse` binding. Bonus: the planner's weight selector now
  shows the Trivial…Fatal labels instead of "Weight N".
- **Editor**: has no event-creation surface (client method only) — no
  dialog to port.

## Version-numbered update banner

The in-app "A new version is available. Refresh to update." banner now
appends the concrete builds — `(v<current> → v<remote>)` — so users can
see exactly which version they're on and which the refresh delivers
(remote version captured from the handshake probe on every poll).

## Verification

Bracket-balance + reference checks; the specific CI failure line
(editor learner.dart:762) is resolved. Pages CI validates on the owner's
push.
