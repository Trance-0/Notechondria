# 0.1.186 - In-note navigation from courses + URLs for every full-screen surface

## In-note links ("what to read next") — root cause

The Veronica-style relative links (`./mamba`, `../../llm/other/architectures`)
resolve correctly in the shell's follow-link handler — but the **course
view opened notes in a bare dialog with no link handler at all**
(`_NoteViewerDialog(note: detail)`, no `onFollowLink`, no routing), and
that's exactly where imported courses are read. Fixed: course/module note
opens now go through the shell's **routed viewer** — `#/note/<uuid>` in
the address bar (unique shareable link), browser Back closes the note,
and in-note relative links follow to the sibling note.

Resolver hardening while at it: `.html` suffixes map back to `.md`, and
site-root-absolute links (`/cv/foundations/filters`) retry with the
source note's content-root prefix (`docs/`).

## URLs for every full-screen surface ("no ajax-like navigation")

- **Portal modules**: opening a module syncs `#/courses/<slug>/m/<key>`
  (slugified module title); backing out restores `#/courses/<slug>` /
  `#/courses`; cold-start module deep links open the module once the
  course's notes load (consumed once; unknown keys stay on the course).
- **Editor + planner tab URLs**: tab switches now sync the hash
  (`#/notes`, `#/courses`, `#/activity`, `#/settings`; planner:
  `#/courses`, `#/activity`, `#/settings`) and cold starts parse it —
  same pattern the portal got in 0.1.179. The editor's existing
  `#/notes/<uuid>` note deep links are untouched (a richer fragment never
  matches a bare tab path). Planner gained the `replaceBrowserPath` shim.
- Dialogs/modal views (event editors, course-edit, pickers) deliberately
  stay URL-less per spec.
