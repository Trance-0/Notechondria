# 0.1.171 - MCP/CLI course-git tools + git-binding logic factored into services

## Context

The owner asked for full MCP/CLI support for remote agents to manage a
course's GitHub binding. This round adds `get_course_git` /
`set_course_git` to **both** MCP servers (parity rule) and factors the
binding logic out of the REST view so all three surfaces share one
implementation.

## What changed

### Shared service (`notes/services.py`)

Moved `course_git_payload` here and added `apply_course_git_binding`
(bind / re-point / tune, arms the lazy-sync debounce, validates the
`owner/name` shape via `GIT_REPO_RE`, raises `CourseGitError` on bad
input, writes the `GIT_BIND` log) and `unlink_course_git` (clears +
`GIT_UNLINK` log). `CourseGitBindingApiView` (0.1.170) now calls these
instead of its own inline logic, so REST and MCP can't diverge.

### MCP tools (both servers — parity)

- `get_course_git(course_id)` — owner-only read of the binding.
- `set_course_git(course_id, repo?, branch?, sync_enabled?,
  sync_timeout_minutes?, unlink?)` — bind/tune, or `unlink: true` to
  clear. Backend tool calls the shared service directly; the CLI proxies
  `GET` / `PUT` / `DELETE courses/<id>/git/` (new `put` added to the CLI
  `BackendClient`). Tool set is now **43** (was 41); the CLI parity
  count test and `docs/server/mcp.md` updated to match.

### Tests

- Backend `mcp/tests.py`: set → get reflects the repo → unlink clears.
- CLI `test_server.py`: `get_course_git` → GET, `set_course_git` →
  PUT (with body) / DELETE on unlink; parity count 43 + both names
  present; `FakeClient` gained `put`.

## Verification

- `python3 -m py_compile` on every edited backend module; CLI
  `python -m unittest discover -s tests` → 26 pass (was 23).
- Django suite not run locally (host budget); `backend-tests.yml`
  (`django-tests` + `cli-tests`) is the authority post-push.
