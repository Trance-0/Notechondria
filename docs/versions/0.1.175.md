# 0.1.175 - GitHub App binding over MCP/CLI + Veronica-7 adapter validation

## Context

Prep for the Veronica-7 migration (step 2 = bind + import). The GitHub
App installation primitives — check install status, link an installation
id, and list the repos the App can reach — existed only as REST views, so
an agent driving the migration over MCP/CLI couldn't "bind the app to a
repo" before `set_course_git` / `import_course_git`. This exposes them on
both tool surfaces and validates the adapter against the real repo.

## What changed (backend)

- **`creators/services/github_sync.py`**: extracted
  `list_installation_repositories(integration)` (paginates
  `/installation/repositories`, raises `GithubSyncError`) so the REST
  repo-picker and the new MCP tool share one implementation.
- **`creators/api.py`**: `GithubSyncReposApiView` now delegates to the
  shared helper (same 400 error contract; disconnected-case test
  unchanged).
- **MCP/CLI parity — three new tools (45→48)**:
  - `github_app_status` → `GET integrations/github/status/` — connected?
    install_url, app name, linked installation id / account.
  - `connect_github_app` → `POST integrations/github/callback/` — persist
    an installation id (idempotent `update_or_create`).
  - `list_github_repos` → `GET integrations/github/repos/` — repos the
    installation can access (`full_name` / `default_branch` / `private`).

## Adapter validation (read-only, real data)

Ran `courses/course_repo.py` against the real
`colorful-numbers/Veronica-7` tree (211 blobs / 195 md) using the GitHub
tree API's path list (so dotfiles like `docs/.vitepress/` are seen as in
production): `infer_preset`→`vitepress`, `.vitepress/**` + `public/**`
excluded, no README/TODO leakage, depth-1 → 6 index-titled modules / 193
notes / 0 warnings, frontmatter round-trips through `compose_markdown`.
**No adapter bug.** Runbook + validated `notechondria.course.yaml`:
`docs/integrations/veronica-7-migration.md`.

Noted (not a regression): imported notes have no per-note `sort_order` —
the course view lists `-last_edit`, so a fresh import shows reverse
reading order. The frontmatter `order`/`sidebar_position` is preserved in
`custom_meta` for a future order-aware course view (TODO).

## Verification

- `python3 -m py_compile` across edited modules; CLI unittest → 29 pass
  (48 tools).
- New MCP tests (mock the repo-list network): `github_app_status`
  reports connected/disconnected, `connect_github_app` persists +
  re-links idempotently, `list_github_repos` returns the installation's
  repos and errors without an integration. Django suite runs in CI.
