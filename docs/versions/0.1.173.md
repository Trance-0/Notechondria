# 0.1.173 - Course git import (repo → notes) via the adapter

## Context

Second step of the course↔GitHub binding: pull a bound repo's markdown
into the course's notes using the 0.1.172 adapter, with the owner's
GitHub App installation token. Idempotent, round-trippable (each note
remembers its repo path).

## What changed (backend)

- **`Note.git_path`** (`notes/0019_note_git_path.py`): the repo-relative
  path a note maps to when its course is bound; empty otherwise. The
  lazy sync (next round) writes back to it.
- **`courses/git_service.py`**:
  - `fetch_course_repo(integration, repo, branch)` — reads the config
    file + the repo tree, fetches **markdown blobs only** (size/count
    capped), via the App token. Isolated so tests mock it.
  - `import_course_from_repo(course)` — `load_course_config` +
    `parse_course_repo`, then create/update notes matched by `git_path`
    (unchanged notes are left alone), writes a `GIT_IMPORT` log, returns
    a summary (`created`/`updated`/`note_count`/`warnings`). Errors
    (no App installation, repo unreachable) raise `CourseGitServiceError`.
- **`github_sync`**: public `installation_token` / `github_request_headers`
  wrappers so the course-git service reuses the App token without
  reaching into privates (the installation covers all its repos).
- **`POST courses/<id>/git/import/`** (`CourseGitImportApiView`,
  owner-only) → summary or 400.
- **MCP/CLI parity**: `import_course_git` in both servers (tool set
  43→44; parity count test + `docs/server/mcp.md` updated).

## Verification

- `python3 -m py_compile` across all edited modules; CLI unittest → 26
  pass (44 tools).
- Tests (mock the network fetch): REST import creates notes with
  `git_path`, is idempotent (re-import updates in place, no duplicates),
  logs `GIT_IMPORT`, and 400s without an App installation; MCP
  `import_course_git` creates notes.
- Django suite runs in CI (`backend-tests.yml`).
