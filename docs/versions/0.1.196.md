# 0.1.196 - Fix: portal (and all web apps) stuck on load — strip the deprecated service worker

**Incident:** the portal web app showed a long loading state and never
rendered; Firefox logged an `NS_ERROR` loading a font
(`FontManifest.json`).

## Diagnosis

Server side was fully healthy — every asset (fonts, `FontManifest.json`,
CanvasKit `.wasm`, both manifests) returned 200 with correct sizes, and
the backend answered boot endpoints in <1s. The failure was **client-side
and Firefox-visible**, the signature of a **stale / looping service
worker**:

- This Flutter SDK **deprecated its service worker** and ships a 784-byte
  *self-destroying* `flutter_service_worker.js` (the bootstrap even
  carries the "service worker is deprecated" notice), yet
  `flutter_bootstrap.js` still **registered it on every load**. A browser
  could get caught re-registering/unregistering that worker, serving a
  broken cached asset mix (→ the font `NS_ERROR`) and never painting.
- The smoke test never sees this: it runs in the Flutter test VM with no
  service worker and empty storage, so it kept passing while real
  browsers hung. (All three apps ship the same worker; portal was simply
  the one being used.)

## Fix

Enabled the repo's own `STRIP_SERVICE_WORKER` kill switch (Actions
variable → `true`) and **hardened the strip step** in
`frontend-pages.yml`:

1. Remove the `serviceWorkerSettings` key from `_flutter.loader.load(…)`
   — now matching both the inline-object *and* minified-variable forms
   (the old regex only matched the inline form, so it silently no-op'd on
   the current SDK). A build-time `assert` fails loudly if the key ever
   survives, so this can't regress silently again.
2. **Keep** a self-destroying `flutter_service_worker.js` at the
   registered URL (the old switch *deleted* it). A browser still holding
   a stale worker now updates to it on the next navigation, unregisters,
   and reloads once — rather than 404-ing on update and staying broken.

Net effect: no service worker is registered going forward (every load
fetches fresh), and already-stuck browsers self-heal on their next visit.
Offline PWA caching is not lost — the deprecated self-destroying worker
never cached anything anyway.

## Verification

- Strip regex validated against the live deployed `flutter_bootstrap.js`:
  `serviceWorkerSettings` is removed, leaving `_flutter.loader.load({})`,
  and the `assert` passes. YAML parses.
- After deploy, confirm on each app that `flutter_bootstrap.js` no longer
  contains `serviceWorkerSettings`, `flutter_service_worker.js` is the
  self-destroying stub, and the bundle serves `0.1.196`.
