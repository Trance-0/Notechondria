## What's Changed

### Environment variable naming consistency

- [x] Unified naming convention: every variable is now prefixed by its subsystem (`DJANGO_`, `POSTGRE_`, `SMTP_`, `FRONTEND_`, `BACKEND_`, etc.) with no unprefixed fallbacks.
- [x] Renamed `SECRET_KEY` → `DJANGO_SECRET_KEY` (removed dual-read fallback in `settings.py`).
- [x] Renamed `DEBUG` → `DJANGO_DEBUG` (removed dual-read fallback).
- [x] Renamed `ALLOWED_HOSTS` → `DJANGO_ALLOWED_HOSTS` (removed unprefixed fallback).
- [x] Renamed `CSRF_TRUSTED_ORIGINS` → `DJANGO_CSRF_TRUSTED_ORIGINS` (removed unprefixed fallback).
- [x] Renamed `CUSTOM_DOMAIN` → `BACKEND_CUSTOM_DOMAIN`.
- [x] Renamed `PRODUCTION_STATIC_ROOT` → `DJANGO_PRODUCTION_STATIC_ROOT`.
- [x] Renamed `PRODUCTION_MEDIA_ROOT` → `DJANGO_PRODUCTION_MEDIA_ROOT`.
- [x] Renamed `EMAIL_VERIFICATION_TTL_HOURS` → `SMTP_EMAIL_VERIFICATION_TTL_HOURS`.
- [x] All three sample env files (`sample.env`, `sample.test.env`, `sample.render.env`) reorganised into labelled sections (Django Core, PostgreSQL, Docker Ports, SMTP Email, Frontend, OpenAI, GitHub App, Docker Images, Docker Infrastructure, Render/MCP) with full spec for every variable including those with code defaults.
- [x] `backend/docker-compose.yml` no longer passes duplicate old-name keys (`SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS`) alongside their `DJANGO_`-prefixed counterparts.
