# 0.1.191 - Editor Inbox default for offline / signed-out users

Follow-up to #30 (reopened): 0.1.190 fixed the *authenticated* Inbox
filter, but signed-out / offline users still landed on the public
discovery feed.

## #30 (reopen) — anonymous default view showed public notes

For a signed-out user the editor booted into "All notes" with
`scope=all`, i.e. the platform-wide public feed — not their Inbox. Two
causes, both fixed:

- **Boot (`initial_data`).** When unauthenticated, the default selection
  is now the **Inbox** (`_uncategorizedSelected = true`), and the
  public-notes fetch is skipped (an anonymous user has no cloud identity
  to list; the public feed belongs to "All notes"). Signed-in boot keeps
  the documented "All notes" default.
- **Reload (`_loadLearnerNotes`).** The anonymous Inbox is treated like
  the local-drafts scope: the cloud list is cleared and no `listNotes`
  call is made, so only local drafts — the intro note for a fresh user —
  are shown.

**Sidebar highlight (both drawer + wide).** The Inbox and "All notes"
rows both carry a null category id, which made them collide. The Inbox
row now highlights on `_uncategorizedSelected`; the "All notes" rows only
when it is false. So exactly one is active at a time, and "All notes"
(public discovery for guests) remains one tap away.

## Verification

Frontend-only; bracket-balanced and reference-checked. The backend
`course_id=none` filter and its tests shipped in 0.1.190. Verified on the
deployed bundle after the Pages build (the 0.1.190 editor build was
cancelled by a concurrency race — re-checked here).

Closes #30
