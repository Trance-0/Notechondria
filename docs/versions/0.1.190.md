# 0.1.190 - Editor Inbox shows only uncategorized notes

Fixes the first bug filed on the new issues board.

## #30 — Inbox listed every note, not just uncategorized ones

The sidebar's Inbox folder is a synthetic row with `id: null` (it is not
a `Course`). Selecting it set `_selectedCategoryId = null` — but that is
*also* the "All notes" state, so both rows produced an identical request
and an identical list. Worse, the note-list call only sent a filter for
a positive id (`courseId > 0 ? id : null`), and the backend only applied
one for a truthy `course_id`, so the Inbox request was completely
unfiltered: every note the user owned, categorised ones included.

**Backend** — `GET /notes/` now accepts `course_id=none` (aliases:
`null`, `uncategorized`) meaning `course_id IS NULL`. Numeric ids and the
no-parameter case behave exactly as before.

**Editor** — a dedicated `_uncategorizedSelected` flag separates the two
states that used to collapse into `null`:

- picking the Inbox row (`is_uncategorized: true`, no id) sets it and
  sends `course_id=none`;
- picking **All notes** clears it (both the drawer and the wide sidebar),
  and those rows no longer render as selected while the Inbox is active;
- category delete / reset paths fall back to All notes and clear it too.

`listNotes` gained an `uncategorizedOnly` flag rather than overloading
`courseId`, so the int-typed id stays honest.

## Verification

Full Django suite in the Docker harness: **258 tests OK**, including new
`UncategorizedNoteFilterTests` — `course_id=none` excludes filed notes,
the `null`/`uncategorized` aliases behave the same, omitting the
parameter still lists everything, and a numeric id still narrows to that
course.

## Note on the rest of #30

"Expected user to click all notes to view all public notes" — All notes
currently honours the existing **scope** selector (`personal` = your
notes, `all` = yours + everyone's public). Making that row *force*
public-discovery would override a control the user already set, so it is
left alone here; say the word and it can become an explicit
"Discover/Public" entry instead.

Closes #30
