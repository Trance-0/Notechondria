# 0.1.132 - i18n plan + architecture doc

## User request

Add i18n support (English US + Chinese Simplified), a Language setting
in each app built from shared widgets, and system-language default
detection — delivered over multiple versions, starting with planning
and documentation.

## What changed

Documentation-only. Authored
[`docs/development/i18n_plan.md`](../development/i18n_plan.md): the full
architecture and phasing for internationalization.

Key decisions recorded:

- **Single shared catalog.** Run `gen-l10n` inside
  `notechondria_shared` with `synthetic-package: false`, output real
  Dart into the package `lib/`, and export `AppLocalizations` from the
  barrel so all three apps and every shared widget use one ARB catalog
  (no per-app duplication). ARBs: `app_en.arb` (template) + `app_zh.arb`.
- **Language preference rides `app_settings`** under key `locale`
  (`system` | `en` | `zh`), mirroring `theme_preset` exactly — no
  backend schema change. A change fires an `onLocaleChanged` callback
  next to the existing `onThemeChanged` and rebuilds `MaterialApp`.
- **System default for free.** The `system` sentinel leaves `locale`
  null so `MaterialApp` follows the device locale clamped to the
  supported set.
- **Language dropdown** added to the shared `AppPreferencesCard`
  (planner uses it directly; editor/portal hand-roll and wire their
  own, same divergence the theme dropdowns already have).
- **§1.8 policy.** Keep diagnostic/log strings English+greppable;
  localize only the user-facing consequence sentence, keeping the
  `module/process` token English in the string.
- **Phasing.** Phase 1 scaffold + editor; Phase 2 planner; Phase 3
  portal; Phase 4 shared-widget/dialog sweep.

## Verification

- Documentation-only; no code or build behavior changed, so no test
  runs this round. Implementation begins in Phase 1 (next version).
