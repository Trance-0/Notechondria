# 0.1.133 - i18n Phase 1: infrastructure + editor language switcher

## User request

Begin implementing the i18n plan ([`development/i18n_plan.md`](../development/i18n_plan.md)),
editor app first: a Language setting, system-language default, and
English (US) + Chinese (Simplified).

## What changed

This is Phase 1 of the phased rollout — the localization pipeline plus
a working language switcher in the **editor** app. Planner and portal
are untouched (still English) and continue to build against the shared
package; their string translation is Phase 2/3.

### Shared package — the localization catalog

- `notechondria_shared` now hosts the single ARB catalog and generated
  `AppLocalizations` consumed by all apps:
  - `l10n.yaml` (`output-dir: lib/src/l10n`, real generated Dart — not
    the synthetic package, so it is importable across packages),
  - `lib/l10n/app_en.arb` (template) + `lib/l10n/app_zh.arb`,
  - generated `lib/src/l10n/app_localizations*.dart` (committed so apps
    build without a generation step; re-run `flutter gen-l10n` in the
    shared package when ARBs change),
  - deps `flutter_localizations` (SDK) + `intl`, `flutter: generate: true`.
- New `lib/src/utils/locale_options.dart`: `kLocaleOptions`
  (System default / English / 简体中文) and `resolveLocale(stored)`
  mapping `app_settings['locale']` (`system` | `en` | `zh`) to a
  `Locale?` (null follows the device).
- Barrel exports `AppLocalizations`, `kLocaleOptions`, `LocaleOption`,
  `resolveLocale`.

### Editor app — language switcher

- `pubspec.yaml`: `flutter_localizations` + `intl`.
- `MaterialApp` (`app_shell.dart`): `localizationsDelegates:
  AppLocalizations.localizationsDelegates`, `supportedLocales`, and
  `locale: _locale`. `_locale` is driven by a new `onLocaleChanged`
  callback that mirrors the existing `onThemeChanged` plumbing exactly.
- Locale persistence mirrors `theme_preset`: `locale: 'system'` in
  `defaultSettings()`, included in `_currentAppSettingsPayload`, and
  applied + persisted immediately through `_applyLocalAppSettings`
  (which now fires `onLocaleChanged`). Boot paths (`load_local_state`,
  `initial_data`) push the saved locale on first paint, so the
  system-language default works for free (a `system` value leaves
  `MaterialApp.locale` null → device locale clamped to the supported
  set).
- A **Language** row in the Editor settings subpage (next to the theme
  pickers), wired to a new `onSetLocale` callback that calls
  `_setLocale` (the offline-mode-style immediate-apply path). The row's
  label and the "System default" option are localized via
  `AppLocalizations`, so switching to Chinese flips them live
  (Language → 语言, System default → 跟随系统) — a visible end-to-end
  proof of the pipeline.

### Scope note

Phase 1 deliberately translates only a small demonstrative string set
(the Language row + the supported-locale autonyms). The ~130 remaining
editor strings, the shared-widget strings, and planner/portal are
translated in later phases per the plan — they keep working in English
via the template fallback. Planner/portal MaterialApps are not yet
wired for a Language setting (Phase 2/3); they follow the device locale
for Flutter's built-in widgets only once wired.

## Verification

- `flutter gen-l10n` in the shared package generates importable
  `AppLocalizations` (validated; the deprecated `synthetic-package`
  flag was removed — Flutter 3.38 generates into the source tree by
  default).
- `flutter analyze` — 0 errors in `notechondria_shared` and `editor_app`.
- `flutter test test/smoke_test.dart` passes in editor.
- `flutter build web --release --base-href /Notechondria/<app>/
  --no-web-resources-cdn` passes for **all three** apps (planner and
  portal still build against the updated shared package).
- No backend changes (locale rides the existing `app_settings` JSON).

## Environment / config notes

- New deps: `flutter_localizations` (SDK) + `intl` in the shared package
  and the editor app. Planner/portal lockfiles updated transitively.
- To add or change strings: edit the ARBs in
  `notechondria_shared/lib/l10n/`, run `flutter gen-l10n` in the shared
  package, and commit the regenerated `lib/src/l10n/`.
