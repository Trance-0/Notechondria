# 0.1.167 - Activity events: per-course colours, hold-to-edit, recurrence dialog

## Context

Owner activity report (continued): "event in activity CSS is wrong —
no visible text in dark theme; add variation of colour and hold (right
click) to edit the event; add a repeat setting for the event (default
one-time, may cycle on week/month/year and may end on a date or after N
occurrences)." The recurrence *backend* landed in 0.1.164; this round
adds the portal UI for all three.

## What changed (portal)

### Legible, per-course event colours

- `_calendarEventColor` now takes the event map and, for planner
  ("plan") events, picks from an 8-colour light pastel palette keyed by
  `course_id`, so different courses are visually distinct. Note
  sessions and external calendar feeds keep their fixed hues.
- New `_calendarEventInkFor(bg)` derives the label colour from the
  tile's luminance (dark ink on light tiles, white on dark ones), so
  the text is never invisible — the old single fixed ink is now just
  the light-tile branch. Both the week/3-day tile and the month chip
  use it.

### Hold / right-click to edit

- Event tiles (`_CalendarEventTile`, `_MonthEventChip`) gained
  `onLongPress`, also bound to `onSecondaryTap` (right-click).
- `_handleEventHold` opens the editor for editable planner events and
  falls back to the read-only detail sheet for calendar/session tiles.
  Wired in the week/3-day grid, the month grid, and the month "+N"
  overflow dialog.

### Edit dialog with recurrence rule

- New `_showEditPlannerEventDialog`: pre-fills title/description/date/
  start+end time/weight and a full recurrence section — frequency
  (does-not-repeat / weekly / monthly / yearly), an interval, and an
  end rule (never / on a date / after N occurrences). On save it PATCHes
  only the writable fields (`recurrence_freq/interval/end_date/count`),
  clearing the unused end field.
- Plumbing: new `_updatePlannerEvent` handler (local + cloud, mirrors
  the completion-toggle path) threaded as `onUpdatePlannerEvent` from
  `app_shell` → `_ActivityPage` → `_WideWeekCalendar` → tiles.
- New l10n keys (`activityEditEvent`, `activityRepeat*`) in the shared
  ARB + committed generated `AppLocalizations` (en + zh).

## Verification

- Interpolation-aware brace/paren/bracket balance passes on every
  edited Dart file; both ARBs parse as JSON. Fixed one Dart type slip
  (`num.clamp` → explicit int bounds) before it could reach CI.
- Flutter build not run locally (host budget) — `frontend-pages.yml` is
  the authority post-push.
