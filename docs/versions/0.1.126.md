# 0.1.126 - cross-platform survey: mobile web gaps, auth-corruption root cause, tutorials plan

## User request

Survey documented bugs and unimplemented features, assess mobile/web
compatibility (the owner uses the apps via Safari bookmarks on iPhone
with no Apple computer available), investigate the "multi app auth is
corrupting" symptom, and produce a detailed progress snapshot plus a
plan for tutorials integration and cross-platform reliability.

## What changed

Documentation-only round; no code changes.

- Added
  [`docs/development/cross_platform_plan.md`](../development/cross_platform_plan.md):
  progress snapshot at 0.1.125, prioritized mobile-web findings
  (F1–F7), tutorials-integration design, phased roadmap (A–D), manual
  cross-platform test matrix, and the open owner decisions.
- **Root cause identified for the multi-app auth corruption (F1):** on
  GitHub Pages all three apps share one browser origin, and web
  `shared_preferences` is origin-scoped — editor / planner / portal
  use identical storage keys (`notechondria.local_*`,
  `notechondria.session` in each app's `lib/core/local_store.dart`,
  plus the unprefixed `oauth_*` handoff keys in
  `notechondria_shared/lib/src/app_shell/app_shell_oauth_mixin.dart:196-198`),
  so the apps overwrite each other's sessions, settings, drafts, and
  OAuth intent. Native desktop builds are unaffected, which is why the
  symptom only appears in browser usage. Fix tracked as the new
  Urgent TODO item (per-app key namespacing + copy-style migration).
- Further findings documented: all three `web/index.html` files lack a
  viewport meta tag (iPhone Safari renders the desktop breakpoint on a
  ~980 px virtual viewport); web identity is still the Flutter
  placeholder ("frontend" / "A new Flutter project." in manifest,
  title, and `apple-mobile-web-app-title`); service-worker disabling
  in `frontend-pages.yml` means web builds cannot launch offline, and
  Safari ITP can evict all local data after 7 days of inactivity;
  `oauth_callback` in `backend/notechondria/api_views.py` hardcodes
  the editor path for all same-tab redirect flows.
- Updated `docs/TODO.md`: new "Cross-platform web shell" subsection
  (Urgent storage-namespacing item, viewport meta, web identity,
  offline/install decision), new "Tutorials" section (course content +
  seeding, in-app surfacing), OAuth-callback app routing and Casdoor
  redirect-URI audit items under Backend / Auth, and rewrote the stale
  Casdoor migration entry — phases 1–3 landed across 0.1.95–0.1.101,
  only phases 4–5 remain.
- Linked the new plan doc from `docs/SUMMARY.md` and
  `docs/readme.md`.
