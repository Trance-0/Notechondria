# 0.1.177 - Portal UI bug batch + note names / in-course links

Eight reported portal bugs. 1–7 are contained UI fixes; 8 lands the
testable core of the note-URL redesign (unique per-course names + in-course
markdown link resolution); the shareable browser-URL router is a scoped
follow-up (see TODO).

## Fixes

1. **Blockquote theme** — note markdown had no `styleSheet`, so
   `flutter_markdown`'s hardcoded (pale-blue) blockquote looked wrong in
   dark/light. Added a theme-derived `_noteMarkdownStyleSheet` (blockquote
   left-accent + surface tint, themed code/codeblock/rule), wired into the
   viewer and the learner preview.
2. **Note-card avatar** — the byline avatar now prefers the Casdoor
   `avatar_url` with `image_url` as fallback (matching the working settings
   account card).
3. **Responsive heatmap** — front-page window widened to a year of history
   (`days_before=364`, `days_after=28`) and the grid now sizes cells to
   span the full row width (left-aligned, trims oldest weeks to fit): wider
   window renders more history, no half-empty row.
4. **Heatmap tooltip** — each day now has a tooltip (`_HeatmapCell`) with
   the date + activity intensity / planned load (new `heatmapActivityValue`
   / `heatmapPlannedValue` l10n).
5. **Removed** the "课程信息可在编辑器详情面板中编辑" hint from note cards.
6. **Courses carousel** — recent public courses are now a swipeable
   `PageView` with a tappable circular dot selector (was a plain horizontal
   `ListView`).
7. **Weight labels** — the difficulty selector maps 1–5 to
   Trivial/Normal/Important/Significant/Fatal instead of "Weight N"
   (`activityWeightN`, en+zh).

## 8. Note names + in-course link resolution

**Backend (`Note.name`, migration `0020_note_name`):** a URL-safe slug,
**unique per course** (partial `UniqueConstraint` on `course_id` + `name`).
Auto-derived — imported notes from the `git_path` basename (`index`/`README`
→ folder name), others from the title — and de-duplicated per course
(`services.ensure_note_name` / `unique_note_name`). Assigned on note create
and git-import; existing notes backfilled by the migration. Exposed as
`name` (+ `git_path`) on the note summary/detail serializers.

**Frontend (in-course navigation):** the note viewer's markdown now has an
`onTapLink` handler. External links open in the browser; a **relative
in-course link resolves to a sibling note** — first by repo path (resolved
relative to the source note's `git_path`, trying `.md` / `/index.md`), then
by slugified name — and opens it (`_followNoteLink` / `_matchCourseLink` in
`note_loading.dart`). This is the "relative link in the same course
seamlessly redirects" behaviour.

**Deferred (TODO):** shareable per-note browser URLs (`/c/<course>/<name>`)
+ deep-link routing. That is a Navigator-2.0 / URL-strategy migration of
`app_shell` best done with a local Flutter build to validate; the naming
foundation here unblocks it.
