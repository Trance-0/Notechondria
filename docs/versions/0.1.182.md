# 0.1.182 - Portal session persistence (root cause) + course/avatar fix round

Nine owner reports + the note-card avatar. Items 1 (edit-dialog course
dropdown), 4 (ctrl+scroll zoom), and part of 2 shipped in 0.1.181 —
this round's root-cause discovery explains the rest.

## CRITICAL root cause (#7 → cascades to #2, #6)

**The portal never persisted the login session** (memory-only token; the
editor persisted, portal deliberately no-op'd). Every page reload signed
the user out silently, which surfaced as: no login info shown (#7), no
subscribed courses in the course list (#6), an empty course list feeding
the activity filter → no category dropdown (#2), and "new project
missing" (#8: courses created while effectively signed out were
device-local to one app). Fixed by porting the editor's session
persistence: `saveSession`/`loadSession`/`clearSession` in the portal
store, `persistSession`/`clearPersistedSession` overrides, and a boot-time
`_restoreSession()` that validates the stored token via `/auth/session/`
(stale tokens are cleared, not restored).

## Other fixes/features

- **#3** — the wide calendar always renders the hour grid now: an empty
  week synthesizes placeholder days (starting today) so offline /
  no-event states keep the drag-to-create surface instead of a "no
  events" card.
- **#5** — create-course dialog gains a colour-hue selector (slider +
  theme-default checkbox + live swatch) and a feature-image URL field;
  local courses store `color_hue` / `cover_image_url`.
- **#6** — subscribed courses (the default scope) now order by last
  viewed, newest first.
- **#8** — editor sidebar categories order by the user's most recent
  activity (last opened, else newest note edit) so a fresh project
  surfaces at the top; the list already contained all owned+subscribed
  rows.
- **#9** — "Import from GitHub repo" in the create-course dialog
  (signed-in): `owner/name` field → create course → bind (`PUT
  /courses/<id>/git/`, one repo per course) → import markdown → open the
  course. New portal client methods `setCourseGit`/`importCourseGit` +
  `_put` verb helper.
- **Avatar (editor + portal)** — two causes: (a) pulled cloud copies
  stamped a hardcoded "Local Draft" author with an empty avatar (visible
  after 0.1.180's post-login pull) — pulled drafts now keep the note's
  real author, and fresh drafts attribute to the signed-in profile;
  (b) the editor never got the portal's 0.1.163/0.1.177 Casdoor→local
  fallback chain — `_RemoteMedia.fallbackUrl`/`_RemoteAvatar.
  fallbackImageUrl` ported and the byline prefers `avatar_url` with
  `image_url` fallback.
