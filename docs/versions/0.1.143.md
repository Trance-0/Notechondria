# 0.1.143 - i18n Phase 2/3: Language setting in planner + portal

## User request

Continue working through `docs/TODO.md`. The next i18n milestone:
planner + portal had the `AppLocalizations` delegate (0.1.140) but no
in-app Language picker — they only followed the device locale. Add a
Language setting to both, mirroring the editor.

## What changed

### Shared `AppPreferencesCard` (planner uses it)

- Localized every string (Default editor, editor-mode options, Theme
  preset, Theme mode + System/Light/Dark, Offline mode + subtitle, View
  tutorial + subtitle, API base URL + lock/helper text) via
  `AppLocalizations`.
- Added an optional **Language** dropdown row: new `currentLocale` +
  `onLocaleChanged` params. When both are non-null the card renders a
  System / English / 简体中文 picker (from `kLocaleOptions`); apps that
  just follow the device locale leave them null.

### Planner + portal locale plumbing (mirrors the editor)

- `app_shell.dart` `_NotechondriaAppState`: added `Locale? _locale`,
  `_handleLocaleChanged` (→ `resolveLocale`), `locale: _locale` on the
  `MaterialApp`, and `onLocaleChanged: _handleLocaleChanged` passed to
  `AppShell` (new `onLocaleChanged` field).
- `settings_helpers.dart`: `_applyLocalAppSettings` now fires
  `widget.onLocaleChanged`, and a new `_setLocale` applies + persists +
  logs the change immediately (no Save button needed — same as theme).
- `load_local_state.dart` + `initial_data.dart`: fire `onLocaleChanged`
  with the persisted `locale` on boot, so a saved language is applied
  on cold start.
- `local_store.dart` `defaultSettings()`: seeds `'locale': 'system'`.
- Settings surface threads `currentLocale` + `onSetLocale`: planner via
  the `AppPreferencesCard` Language row; portal via a new Language row
  in its `_PortalPreferencesPage` (with `_pickLocale` / `_localeLabel`,
  mirroring the editor's preferences subpage).

### What's-New

- Appended a `0.1.143` "Choose your language" `FeatureUpdate` to
  planner's and portal's `whats_new.dart` registries (standing
  convention for user-visible features).

## Verification

- New `planner_app/test/locale_switch_test.dart` +
  `portal_app/test/locale_switch_test.dart`: a persisted `locale: zh`
  boots each app in Chinese (`Localizations.localeOf == zh`,
  `prefsLanguage == 语言`).
- `flutter analyze` — 0 errors/new warnings across shared + all three
  apps.
- `flutter test` — shared suite + all three apps (incl. the new locale
  tests).
- `flutter build web` — all three apps pass.

## Notes / environment

- Toolchain hiccup this round: the Flutter tool hung at startup after a
  killed `gen-l10n` left a stale `bin/cache/lockfile`. Deleting that
  lockfile (and running with `CI=true` / one flutter command at a time,
  not orphaning processes) restored it. No repo change needed.
