# 0.1.134 - planner Activity view works offline (no sign-in required)

## User request

The Activity view was sign-in only; fix it so it loads cached/local
data from the browser like the rest of the app.

## Root cause

In `planner_app/lib/core/initial_data.dart`, the signed-out branch of
`_loadInitialData` blanked the planner state it had just loaded from
the local cache at boot:

```dart
} else {
  plannerEvents = const [];
  activityWeek = null;   // <- wiped the cached/seeded activity board
  ...
}
```

`plannerEvents` and `activityWeek` are seeded on first run
(`local_starter.dart`) and persisted in the local cache, but this
branch overwrote them with empty/null whenever no token was present —
so the Activity board showed only the "sign in to view…" empty state.
The interactive week navigator (`_loadActivityWeek`) also early-returned
when signed out, leaving the board blank when paging weeks.

## What changed

`frontend/planner_app/lib/core/initial_data.dart` — the signed-out
branch now KEEPS the locally-loaded `plannerEvents` and rebuilds the
activity board from them with `_buildOfflineActivityWeek()` (the same
offline builder the first-run seed uses), instead of blanking. Cloud-
only data (calendar feeds, server recycle bin, cloud notes) has no
local equivalent and is still cleared.

`frontend/planner_app/lib/core/settings_actions.dart` —
`_loadActivityWeek` now, when signed out, sets the requested week start
and rebuilds the offline board instead of returning early, so paging
weeks works offline.

Net effect: the Activity view renders the user's local/seeded planner
events offline and signed-out, matching how courses already render
from cache.
