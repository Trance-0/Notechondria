# 0.1.166 - Activity import feedback (backend summary + portal result modal)

## Context

Owner report: "After ICS or subscription import in activity, [I]
expected a modal showing if the import succeeded or not, what events
are imported in a short bullet list — or if it failed, what went wrong.
Currently there is no feedback on activity import." This round adds
that feedback, backend-first (per TODO rule 1).

## What changed

### Backend: import summary on feed create

`summarize_calendar_feed(feed)` (`notes/services.py`) parses a
just-saved feed (reusing `read_calendar_feed` + `parse_ical_events`)
and returns a compact `{"ok", "count", "events": [{title, starts_at}…],
"error"}`. It never raises: a failed fetch, an HTML sign-in page
(private Google calendar), or a feed with no VEVENTs comes back
`ok=False` with a human-readable `error`.

The calendar-feed `POST` response now carries this under
`import_summary` (the feed is still created either way — the summary is
purely feedback). Subscriptions (`source_url`) are fetched once
synchronously, exactly as the week payload already does.

Tests (`HeatmapApiTests`): a valid inline feed returns
`ok=True, count=1` with the event title; an empty `VCALENDAR` returns
`ok=False, count=0` with an error string.

### Portal: import-result modal

- `_importCalendarFeed` / `_subscribeCalendarFeed` (`core/calendar.dart`)
  now return the backend `import_summary` (or null) and log the event
  count.
- The `onImportCalendar` / `onSubscribeCalendar` callback types
  (`modules/activity.dart`) changed from `Future<void>` to
  `Future<Map<String, dynamic>?>`.
- New `_showImportResultModal` (`modules/activity_week.dart`): a success
  dialog with a scrollable bullet list of imported events
  (`title — formatted start`), or a failure dialog with the error text.
  Both the file-import path and the subscribe dialog show it, and both
  catch transport/"not signed in" errors into the same failure modal.
- New l10n keys `commonOk`, `activityImportSucceeded`,
  `activityImportFailed`, `activityImportedCount(count, title)` in the
  shared `app_en.arb` / `app_zh.arb` and the committed generated
  `AppLocalizations` (en + zh).

## Verification

- `python3 -m py_compile` on the edited backend modules; both ARB files
  parse as JSON; an interpolation-aware brace/paren/bracket balance
  check passes on every edited Dart file.
- Django suite + Flutter build not run locally (host budget);
  `backend-tests.yml` and `frontend-pages.yml` are the authority
  post-push.
