# 0.1.151 - Handshake exposes `min_frontend_version` (compat floor)

## Context

First half of the version-update notification feature (owner picked
**handshake-compare, no GitHub** + **add a `min_frontend_version`
floor**). This round adds the backend field the frontend will compare
against; the frontend banner lands next.

## What changed

`GET /api/v1/handshake/` now returns a `min_frontend_version` field —
the lowest frontend build the backend still considers compatible. A
running client compares its own built version against this floor: below
it → a stronger "please update" prompt; at or above → the normal soft
"new version available" banner (driven separately by comparing the
client version against the live `version` field, already present).

- `notechondria/api_views.py`: new `_min_frontend_version()` reads the
  `MIN_FRONTEND_VERSION` env var (empty string = "no floor", the
  default), added to the handshake JSON.
- Env-driven so the floor can be raised at deploy time without a code
  change.

## Verification

- `notechondria/tests.py` `HandshakeEndpointTests`: assert the field is
  always present (string), and a new test pins the env override
  (`MIN_FRONTEND_VERSION=0.1.140` → reflected; unset → `""`).
- `manage.py test notechondria.tests.HandshakeEndpointTests` — 5 pass.

## Environment

- Optional new env var **`MIN_FRONTEND_VERSION`** on the backend. Leave
  unset (default) for no floor. Set it (e.g. `0.1.140`) to force clients
  older than that to show the update-required prompt once the frontend
  banner ships.

## Follow-up (0.1.152)

Frontend: a shared version-status util + update banner, each app probing
the handshake on boot + a periodic poll, comparing `_kAppVersion`
against the backend `version` / `min_frontend_version`, with localized
"new version available / rolling out / update required" messages and a
Refresh action.
