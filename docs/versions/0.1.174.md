# 0.1.174 - Course git sync (notes → repo) lazy-on-request

## Context

Third and final step of the course↔GitHub binding: push the course's
notes back to its bound repo as markdown, using the owner's GitHub App
installation token. Backend is the source of truth; only mapped
markdown files are written — never build config, code, or CI. Fires
lazily (no worker/cron): edits arm a debounce, and the next authenticated
course-list poll flushes any course whose timer has elapsed.

## What changed (backend)

- **`courses/course_repo.py`** (adapter write side):
  - `compose_markdown(frontmatter, body)` — re-emits YAML frontmatter +
    body (round-trips the metadata preserved on import so the repo's
    site rendering isn't stripped).
  - `load_frontmatter_dict(raw_json)` — parses a note's `custom_meta`
    back to a dict (`{}` on error).
  - Import now records each note's `frontmatter`.
- **`courses/git_service.py`**:
  - `serialize_course_for_sync(course)` → `{repo_path: markdown}` for the
    course's `.md`-`git_path` notes only (frontmatter re-emitted).
  - `_commit_files(...)` — Contents API PUT per file via the App token
    (GET existing sha → PUT), returns the last commit sha.
  - `sync_course_to_repo(course)` — serialize + commit; clears
    `git_pending_since`, sets `git_last_synced_at`, records
    `git_last_sync_error` on failure; writes a `GIT_SYNC` log.
  - `mark_course_pending(course)` — arms `git_pending_since` on edit for
    a bound, sync-enabled course (debounce start).
  - `flush_due_course_syncs(creator, limit=3)` — pushes any course past
    its `git_sync_timeout_minutes`; **row-locked** (`transaction.atomic`
    + `select_for_update`) so concurrent requests can't double-push;
    best-effort (a failing course records its error and is skipped,
    never breaking the caller).
- **`notes/api.py`**:
  - `POST courses/<id>/git/sync/` (`CourseGitSyncApiView`, owner-only) —
    the explicit "sync now" button → summary or 400.
  - `arm_course_sync(note)` wired into the three note-write paths
    (create / detail patch / by-uuid patch).
  - `CourseListApiView.get` flushes due syncs on every authenticated
    poll (lazy-on-request), failures swallowed so listing never breaks.
- **MCP/CLI parity**: `sync_course_git` in both servers (tool set
  44→45; parity count test + `docs/server/mcp.md` updated).

## Verification

- `python3 -m py_compile` across all edited modules; CLI unittest → 26
  pass (45 tools).
- Django tests (mock `_commit_files`, no network): `POST .../git/sync/`
  serializes notes (frontmatter preserved), pushes, clears
  `git_pending_since`, sets `git_last_synced_at`, logs `GIT_SYNC`;
  editing a note in a bound sync-enabled course arms
  `git_pending_since`; `flush_due_course_syncs` fires past the timeout
  and skips courses still inside it. Django suite runs in CI
  (`backend-tests.yml`).
