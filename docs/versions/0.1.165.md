# 0.1.165 - CI green: stdlib-only CLI client + corrected avatar settings test

## Context

`backend-tests.yml` had two jobs red **before** this round (already
failing on 0.1.163/0.1.164): `cli-tests` and `django-tests`. Neither
reproduced on the dev host (the host happens to have `requests`
installed and cannot run the Django suite at all), so they slipped in.
This round makes both jobs green.

## What changed

### CLI is now genuinely dependency-free (`cli-tests`)

The `cli-tests` job is labelled "stdlib only" and does no `pip
install`, but `notechondria_mcp/client.py` imported `requests`, so test
collection died with `ModuleNotFoundError: No module named 'requests'`.

`BackendClient` was rewritten on top of `urllib.request` (stdlib) with
the same public surface (`get/post/patch/delete`, `BackendError(status,
detail)`, timeout, bearer-key header, 204/empty handling, JSON error
detail extraction). `requests` was removed from `pyproject.toml`
`dependencies` (now `[]`), so the CLI runs with a bare Python install
and the CI contract is honest. No tool/handler behaviour changed (the
tests use a `FakeClient`).

### Corrected the avatar settings-payload test (`django-tests`)

`CasdoorAvatarClaimSyncTests.test_settings_payload_exposes_local_upload_separately`
(added in 0.1.163) asserted `image_upload_url == ''` for a fresh
creator, but `ensure_creator` always attaches a **default** profile
image, so the local upload URL is legitimately non-empty — that default
is exactly the local fallback the SPA uses when the Casdoor avatar
fails to load. The implementation is correct; the assertion was wrong.
The test now asserts `image_upload_url` is truthy, contains `/media/`,
and is distinct from the Casdoor `avatar_url` (the `avatar_url` /
`image_url` assertions are unchanged).

- Django suite still not runnable locally (host budget); `backend-tests.yml`
