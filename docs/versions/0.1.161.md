# 0.1.161 - Pages CI split (frontend/docs independent), backend-tests CI, no-local-containers rule

## Context

The 0.1.160 push failed the Pages workflow: the mdBook sanity check
correctly caught that `docs/SUMMARY.md` did not list
`versions/0.1.160.md` — and because the docs build lived inside
`frontend-pages.yml`, the failure also blocked the frontend deploy.
The owner also ruled: this project is deployed via GitHub Pages
(frontend) + Northflank CI/CD (backend) and must never run in local
Docker on small machines.

## What changed

### SUMMARY.md drift fixed

Added the missing `versions/0.1.158.md`, `0.1.159.md`, `0.1.160.md`
entries (0.1.158's was already absent before the check tripped) and
listed `testing/agent_remote_testing.md`. This file's own entry is
included — the docs leg fails without it.

### Pages deployment split: frontend and docs are now independent

- New `.github/workflows/docs-pages.yml`: mdBook build + the
  SUMMARY-drift check, publishing `docs/build` to the `gh-pages`
  `docs/` subtree (`destination_dir: docs`, `keep_files: true`).
- `frontend-pages.yml` no longer builds docs; it publishes only
  `editor/ planner/ portal/ index.html .nojekyll` with
  `keep_files: true`, so each leg overwrites only its own subtree.
- Both workflows share the `gh-pages-publish` concurrency group so
  the two branch pushes cannot race.
- Result: a docs failure (like 0.1.160's) can no longer block an app
  deploy, and a Flutter failure cannot block a docs deploy.

### New backend-tests CI leg

`.github/workflows/backend-tests.yml` runs the Django suite
(python 3.11, `settings_test`, in-memory sqlite) and the CLI unit
tests on every push touching `backend/**` / `cli/**`. This replaces
local test containers as the canonical backend verification.

### No-local-containers rule (docs/AGENTS.md)

New "Deployment topology & no-local-containers rule" section: never
create local containers for this project on machines with < 16 GB RAM
(the dev host has 3.3 GiB and was crashed by a build once). Frontend =
Pages, backend = Northflank on commit, suites = CI. The local stack,
its five images, and the postgres volume were removed from the dev
host this round. `docs/testing/agent_remote_testing.md` was rewritten
around the CI-first verification table; the Docker instructions remain
only as reference for ≥ 16 GB self-host targets. The TODO round-end
convention now matches.

## Verification

- CLI suite on host python: 23 tests OK.
- Both workflow files parse as valid YAML; the docs leg's SUMMARY
  check passes locally by construction (entry added; verified the
  0.1.161 entry resolves against `docs/versions/`).
- NOT run locally (per the new rule): Django suite, Flutter tests,
  mdBook build — all proven by CI on the next push
  (`backend-tests.yml`, `frontend-pages.yml`, `docs-pages.yml`).
