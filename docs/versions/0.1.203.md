# 0.1.203 - Local folder index cache extracted (L2A2-5)

This round starts the hardening follow-ups before Phase 4
([`development/local_folder_mode/next_phase.md`](../development/local_folder_mode/next_phase.md)
section A, "Do first"). It is a pure refactor: no user-visible behaviour
changes.

## What changed for users

Nothing. The local folder mode behaves exactly as in 0.1.202.

## What landed in code

- `notechondria_shared`: the in-memory index cache moved out of
  `src/local_folder/local_folder_controller.dart` into a new
  `src/local_folder/folder_index_cache.dart` as `FolderIndexCache`
  (deferred item L2A2-5). The class owns the index state (`_index`, the
  unverified set, the scan-time change log, the flush timer and dirty
  flag, and the scan progress) and the methods that touch it
  (`setIndex`, `scan`, the scanner factory, `isUnverified`,
  `updateIndex`, the coalesced flush, and `flushIndex`). It is
  controller-free like `folder_index.dart`: it reads the controller's
  live folder handle, record, lock name, and `active` state through the
  accessors it is built with, mirroring how `FolderScanner` takes its
  collaborators, and calls back into the controller's `notifyListeners`
  for progress and index changes.
- The controller keeps thin `index`, `progress`, `isUnverified`,
  `updateIndex`, `flushIndex`, and `rescan` delegators, so the transport,
  the router's `RouteContext`, the handlers, and every test are
  unchanged. The top-level `kIndexFlushDelay` constant moved with the
  cache and is re-exported from the controller file so the existing
  direct imports in tests still resolve.
- `local_folder_controller.dart` dropped from 892 to 788 lines, back
  under the 1.6 1000-line cap, so Phase 4's change handling (which lands
  in this code) has room.
