# 0.1.162 - Offline activities, Google-style month view, debug-log order, rotation logging

## Context

Owner bug/feature list: (1) offline users cannot create activities,
(2) API key rotation failed with (3) no effective log produced,
(4) the 1-month calendar range was unusable (30 hour-grid columns) and
should read like Google Calendar's month view, (5) the debug log
should show the latest entry at the bottom and auto-scroll.

## What changed

### Offline / signed-out activity creation (portal)

- New device-local planner-event store
  (`notechondria.portal.local_events`, `_LocalAppStore.saveEvents`,
  loaded into `_AppShellState._localEvents`; counted in the
  StorageUsageCard buckets; wiped by "Clear all local data").
- `_createPlannerEvent` without a cloud session now stores the event
  locally (`id: local-<µs>`, `is_local: true`) instead of returning a
  "sign in first" error, with §1.7 info logging.
- `_loadActivityWeek` + both `_loadInitialData` boot paths build a
  local calendar payload for guests (`_localWeekPayload`, mirroring
  the server `calendar_week_payload` shape) and splice local events
  into server payloads for signed-in users
  (`_mergeLocalEventsIntoWeek`), so events created while signed out
  stay visible after sign-in. No automatic upload — cloud sync of
  local events is a follow-up.
- `_togglePlannerEventCompletion` completes/reopens local events in
  the local store (string `local-*` ids never hit the PATCH path).
- The Activity page no longer blocks signed-out users with the
  full-surface sign-in prompt; the calendar + create FAB always
  render. (`activitySignInPrompt` ARB key is now unused; removal
  deferred to the next gen-l10n round.)

### Month calendar = month grid (portal)

`_WideWeekCalendar` with the 1-month range now renders
`_MonthCalendarGrid` instead of 30 hour-grid columns: weekday header,
weeks as rows, each day cell shows the date (today = filled circle,
month shown on the 1st) plus up to a few **prioritized** event chips —
open plans first (heaviest `difficulty_weight`, then earliest start),
feed/session entries next, completed last (dimmed + struck through) —
with a locale-neutral `+N` overflow that opens a day dialog listing
everything. Tap a chip for details, tap an empty cell to create an
event at that date. Zoom controls hide in month mode (no hour rows);
swipe/arrow navigation still shifts by the range length. No new l10n
keys needed.

### API key rotation: diagnosis + effective logging

The deployed backend rotates fine; the reported failure matches an
**expired Casdoor session** — the app renders from local cache so it
looks signed in, but this direct server call 401s. Fixes are on the
observability side:

- Portal + editor `onRotateApiKey` callbacks now log §1.7-shaped
  entries (`Portal.UI`/`Editor.UI` `api_key.rotate`) on success AND
  failure — the failure entry names the cause and the "sign in again"
  remedy — then rethrow so the existing SnackBar still shows.
- Shared `decode()` empty-body ≥400 path used to throw a bare
  `Request failed with <status>` with **no debug snapshot and no
  §1.7 shape** — a fully invisible failure. It now records a snapshot
  and throws the shaped message.

### Debug log: latest at bottom + auto-scroll (all three apps)

The shared debug-log list renders with `reverse: true`: entries
(stored newest-first) now read chronologically with the latest at the
bottom, pinned to the newest entry as lines arrive unless the user
has scrolled up (chat UX). The in-card terminal already auto-scrolled.
