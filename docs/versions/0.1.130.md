# 0.1.130 - first-run onboarding tour

## User request

Continue working on tutorials. The remaining Tutorials TODO item was a
first-run guided tour, previously deferred because anchored coach
marks would need authoring twice around the 960 px drawer/sidebar
breakpoint and would break on UI refactors.

## What changed

Implemented the first-run tour as a **layout-agnostic paged intro**
instead of anchored coach marks — concept cards (icon + title + body)
that never point at a specific on-screen widget, so the same content
renders identically on the mobile drawer layout and the desktop
sidebar layout. This delivers the onboarding the owner originally
asked for while sidestepping the fragility that caused the deferral.

### Shared widget

- New `notechondria_shared/lib/src/components/onboarding_tour.dart`:
  `TourStep` (icon/title/body) and `showOnboardingTour(context,
  appTitle, steps)` — a blur-backed, skippable, swipeable `PageView`
  dialog with a page-dot indicator, Back/Next, Skip→Close on the last
  page, and Done. Exported from the package barrel.

### Per-app onboarding

- New `lib/core/onboarding.dart` part in each app with an app-specific
  `_kOnboardingSteps` registry (editor: notes/categories/sync/settings;
  planner: courses/deadlines/offline/settings; portal: hub/explore/
  launch) and an `_AppShellOnboardingX` extension exposing
  `_maybeShowOnboarding()` (first-run, tracked by an `onboarding_seen`
  local-stats flag) and `_replayOnboarding()` (Settings entry point).
- Wired post-boot in each `initial_data.dart`: on a brand-new user's
  first boot the tour shows and **suppresses the What's-New / install
  nudges that boot** (`if (!_maybeShowOnboarding()) { whatsNew;
  installBanner; }`) so a new user meets one overlay, not three.
  Returning users (flag set) get the existing nudges as before.

### Replay entry point (all three apps)

- Added an optional `onReplayTour` callback:
  - editor + portal: a "View tutorial" row in the Settings menu card
    (plumbed through each `_SettingsPage` + host build site);
  - planner: a "View tutorial" row in the shared `AppPreferencesCard`
    (new optional `onReplayTour` param), wired from planner's
    `_SettingsPage`.

### Tests

- New `onboarding_tour_test.dart`: opens on step one, advances with
  Next, Next→Done + Skip→Close on the last step, Done/Skip close the
  tour, and empty steps render nothing.

## Verification

- `flutter analyze` — 0 errors across `notechondria_shared` and all
  three apps (pre-existing warning backlog unchanged).
- `flutter test` — shared suite passes (incl. the 4 new tour tests);
  all three apps' `test/smoke_test.dart` pass with the tour now firing
  on the first-boot smoke scenario (the underlying starter content
  stays findable behind the modal).
- `flutter build web --release --base-href /Notechondria/<app>/
  --no-web-resources-cdn` passes for all three apps.
- No backend changes this round.

## Notes for the owner

- The tour is intentionally not anchored to UI elements, so it will
  not drift when screens are refactored and needs no per-breakpoint
  authoring. Edit the step copy in each app's
  `lib/core/onboarding.dart`.
- A returning user who already has local data will not see the tour
  (the `onboarding_seen` flag is only unset on a truly fresh install
  or after a full local-data clear); they can replay it any time from
  Settings → "View tutorial".
