# 0.1.163 - Drag-to-draw events, heatmap auto-fit, Casdoor avatar fallback

## Context

Owner list this round: (1) enable drag-and-draw event creation in the
horizontal 3-day / 1-week calendar; (2) the portal heatmap does not
span the horizontal space and should auto-fit the window on mobile and
desktop; (3) the Casdoor avatar is not correctly processed/updated —
when Casdoor is offline use the legacy uploaded avatar, when Casdoor is
read always use the Casdoor avatar.

## What changed

### Drag-to-draw event creation (portal, 3-day / 1-week)

The hour-grid create gesture is now a **plain vertical drag** (was a
long-press) that draws the event's real time span — the drawn band's
start AND end become the new event's start/end (previously the end was
discarded and every event defaulted to one hour). The vertical drag
wins the gesture arena over the parent scroll (scroll the grid via
wheel / scrollbar / hour-label column); the outer horizontal drag
still navigates weeks. A near-zero drag (tap) falls back to a one-hour
block. The create dialog gained a start/end time pair; `endsAt` is
plumbed through `onCreatePlannerEvent` (new named-optional param) into
both the cloud and device-local create paths. The backend already
forces `ends_at > starts_at`.

### Heatmap auto-fit (portal front page)

`_HeatmapSection` rendered ~53 weeks of fixed 13 px cells inside a
horizontal scroll view, so it overflowed on phones and left wide cards
half-empty. It now uses a `LayoutBuilder` to show the most recent weeks
that fit and scales the cell size (9–16 px) so the grid spans the
available width in a fixed-height band on both mobile and desktop. No
horizontal scroll.

### Casdoor avatar: robust claim + offline fallback

Root causes + fixes:

- **Backend claim.** `CASDOOR_CLAIM_AVATAR` defaulted to `avatar`
  only — Casdoor's custom token field, present only when the operator
  enabled it in the application Token Format. Tokens carry the
  **standard OIDC `picture`** claim by default. Default is now
  `avatar,picture` (`_claim_str` takes the first non-empty), so
  avatars resolve regardless of token-format config.
- **Backend payload.** `image_url` was `avatar_url or local` — once a
  Casdoor `avatar_url` was set, the locally-uploaded image URL was
  never sent, so the SPA had no fallback when the Casdoor image failed
  to load. Both the login/exchange payload and the settings serializer
  now also expose `image_upload_url` (the local upload, always);
  `image_url` stays the effective avatar for backward compatibility.
- **Frontend fallback (portal).** The avatar widget (`_RemoteMedia` /
  `_RemoteAvatar`) now takes a fallback URL: it shows the Casdoor
  `avatar_url` first and, when that is empty or fails to load (Casdoor
  offline / 404), falls back to the local `image_upload_url`, then the
  initials placeholder. This realizes "Casdoor when readable, legacy
  uploader when Casdoor is offline." Older payloads without the new
  fields fall back to `image_url`.

Editor and planner get the backend fixes immediately (shared); porting
the frontend on-error fallback into their avatar widgets is a
follow-up (they retain the prior effective-`image_url` behavior, not a
regression).

## Verification

- Backend: `py_compile` clean on the changed modules; new
  `CasdoorAvatarClaimSyncTests` (avatar-vs-picture claim precedence +
  `image_upload_url` exposure in the settings payload). Full Django
  suite runs in `backend-tests.yml` CI on push (no local containers on
  this host).
- Deployed probe (`ntc_…` key): the reporting account's
  `avatar_url` / `image_url` already resolve to the Casdoor avatar,
  confirming the sync path; the fix hardens the claim source and the
  offline fallback.
- Frontend: not built locally (no Flutter toolchain / no-local-
  containers rule) — proven by `frontend-pages.yml` CI on push.
  Bracket-balance checks pass on every touched Dart file; no new l10n
  keys (the drag dialog reuses existing keys; heatmap has no strings).
- What's-New: two portal `FeatureUpdate` entries (drag-to-draw,
  heatmap) added per the standing convention.

## Environment variables

- `CASDOOR_CLAIM_AVATAR` default changed from `avatar` to
  `avatar,picture`. Operators who set it explicitly are unaffected;
  those relying on the default now also pick up the OIDC `picture`
  claim.
