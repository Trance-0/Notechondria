# 0.1.127 - storage namespacing fix, Casdoor password sync, What's-New overlay, mobile web shell

## User request

Implement the three owner decisions from the 0.1.126 cross-platform
survey, then continue down `docs/TODO.md`:

1. Re-enable the Pages service worker with an in-app "new version
   available — reload" toast.
2. Replace the course-based tutorial proposal with a UI overlay that
   introduces missed features on app version updates, tracked per
   user (`last seen version` on the profile) with a skip option.
3. Keep the email/password Casdoor-outage fallback permanently and
   auto-sync the Casdoor password into the app database on Casdoor
   login (Casdoor app config: JWT-Custom, RS256, token fields
   Password / Password salt / Password type; test account provided).

## What changed

### Backend — Casdoor password sync (fallback login stays correct)

- New `backend/creators/casdoor_password.py`:
  - `sync_password_from_claims` mirrors the JWT-Custom credential
    claims (`password` / `passwordSalt` / `passwordType`) into
    `User.password` — `plain` via `set_password`, `bcrypt` stored as
    `bcrypt$<hash>` for Django's `BCryptPasswordHasher`. **Verified
    live against auth.trance-0.com: current Casdoor scrubs the
    `password` claim value (empty string; `passwordType` = bcrypt),
    so this path is dormant until the IdP emits the hash.** Tracked
    in `docs/TODO.md` (watch upstream).
  - `password_grant` runs Casdoor's ROPC grant
    (`/api/login/oauth/access_token`, `grant_type=password`) and
    verifies the returned JWT, distinguishing `rejected` (Casdoor
    answered no) from `unreachable` (timeout / 5xx — the outage case).
    Live-verified with the Alice test account: correct credentials →
    `ok` + verified `sub`; wrong credentials → `rejected`.
- `LoginSerializer` (`backend/creators/api.py`): when the submitted
  password fails the local hash, the backend asks Casdoor via
  `password_grant` (with one username-variant retry); on success and
  a `sub` match against `Creator.casdoor_sub`, the verified plaintext
  is stored locally via `set_password` and login succeeds. Outcome:
  the current Casdoor password always works on the fallback endpoint
  while Casdoor is up, and the locally synced hash serves outages.
  Unlinked legacy accounts never trigger the grant (no auto-bind,
  consistent with the 0.1.118 link-challenge policy).
- `_sync_creator_from_claims` (`casdoor_auth.py`) additionally calls
  the claims-based password sync on its existing 5-minute throttle.
- `settings.py`: explicit `PASSWORD_HASHERS` (Django defaults minus
  Argon2, plus `BCryptPasswordHasher`), `CASDOOR_CLAIM_PASSWORD*`
  claim-name mappings. `bcrypt>=4,<5` added to `requirements.txt`
  and `requirements-render.txt`. `settings_test.py` gained
  `BCryptPasswordHasher` so the sync path is testable.

### Backend — per-app What's-New tracking

- `Creator.last_seen_versions` (JSONField, migration
  `creators/0035`): map of app id → newest version whose feature
  overlay the user has seen or skipped.
- Exposed in `auth_payload` and the settings GET; PATCH
  `/api/v1/settings/` **merges** keys (editor stamping `editor`
  cannot erase planner's entry) and validates shape/size.

### Frontend — What's-New overlay (owner's tutorial design)

- Shared `notechondria_shared`: `FeatureUpdate`, `compareAppVersions`,
  `selectMissedUpdates`, `showWhatsNewOverlay` (blur dialog, feature
  cards, Skip + Got it — both stamp the current version).
- Each app: `lib/core/whats_new.dart` part file with a per-app
  feature registry and `_maybeShowWhatsNew`, hooked at the end of
  `_loadInitialData`. Last-seen resolution: max(local stats,
  signed-in profile map); fresh installs stamp silently instead of
  replaying history. **Standing convention:** rounds that ship a
  user-visible feature append a registry entry in the same commit.

### Frontend — urgent storage-collision fix (multi-app auth corruption)

- Root cause from 0.1.126 fixed: `_LocalAppStore` keys are now
  per-app (`notechondria.editor.*` / `.planner.*` / `.portal.*`),
  with a one-time copy-style `_migrateLegacyKeys` for the old
  unprefixed values (copy, not move — each app migrates
  independently; legacy keys left behind for a later cleanup
  action). Editor's session blob included.
- Shared OAuth handoff keys (`oauth_redirect_uri` /
  `oauth_invitation_code` / `oauth_intent`) are now prefixed with the
  launching app's namespace (derived from `logAppTag`), with a
  legacy-read fallback for flows in flight across the deploy.

### Web shell — mobile fixes + service worker

- All three `web/index.html`: added the missing viewport meta
  (`width=device-width, initial-scale=1, viewport-fit=cover` — iPhone
  Safari previously rendered the desktop breakpoint on a ~980 px
  virtual viewport), real titles/descriptions, per-app
  `apple-mobile-web-app-title`, and a service-worker update toast
  (plain JS; offers a one-tap reload when a new build's worker
  installs behind a controlled page).
- All three `web/manifest.json`: real `name` / `short_name` /
  `description`, `orientation: any`. Icons remain stock Flutter —
  tracked in `docs/TODO.md`.
- `.github/workflows/frontend-pages.yml`: the unconditional
  service-worker strip is now a **kill switch** — workers ship
  enabled (web apps can launch offline; Safari bookmark / home-screen
  usage survives airplane mode after first load); setting the
  repository variable `STRIP_SERVICE_WORKER=true` restores the
  pre-0.1.127 always-network behavior.
