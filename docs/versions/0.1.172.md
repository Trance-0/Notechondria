# 0.1.172 - Course-repo adapter: config format + parser + presets

## Context

Owner locked the course↔GitHub binding architecture: **per-user GitHub
App** auth (bot PAT only for the template/standard), **lazy-on-request**
sync (no worker/cron), and — crucially — the template is a *reference
adapter*, not a mandated layout. You bind an **existing** docs repo
(VitePress / Nextra / Docusaurus / GitBook) and we map its markdown onto
a course **without moving files**, reading/writing **markdown only** and
never touching build config, framework code, or CI. This round lands the
adapter's foundation (everything else — import, sync, UI — consumes it).

Grounded in the real target: `colorful-numbers/Veronica-7` is a live
VitePress project (`docs/**/*.md` content, `docs/.vitepress/` build
config, `.github/workflows/deploy.yml`), so the parser is validated
against that shape.

## What changed

### `backend/courses/course_repo.py` (Django-free, unit-testable)

- **Config**: `notechondria.course.yaml` (optional; YAML or JSON) with
  per-framework **presets** (`vitepress`/`nextra`/`docusaurus`/`gitbook`/
  `custom`) merged over base defaults. `infer_preset()` detects the
  framework from the file tree when there's no config. Course
  title/slug fall back to the repo name.
- **Parser** `parse_course_repo(files, config)`: filters markdown under
  `content.root` by include/exclude globs (a `**`-aware matcher), groups
  into **modules** by the `module_depth`-th path segment, extracts
  **titles** (frontmatter → first H1 → humanized filename; index/README
  names the module), and **orders** by frontmatter `sidebar_position`/
  `order`/`nav_order` (index first, then path). Honors
  `notechondria_ignore` / `draft`.
- **v1 = markdown only**: `.mdx` is skipped and reported in `warnings`
  (MDX support deferred — TODO). Non-markdown, `.vitepress/`, CI, and
  files outside the content root are ignored.

### Supporting

- Added **PyYAML** (`>=6,<7`) to `requirements.txt` +
  `requirements-render.txt` (frontmatter and config are YAML; the repo
  previously avoided a YAML dep by requiring JSON-only configs).
- `docs/integrations/course-repo-format.md`: the published **standard**
  (principle, config schema, preset table, mapping rules, sync/auth
  summary).

## Verification

- `python3 -m py_compile` on the module + tests; the parser assertions
  run standalone (no Django) and pass — inferred vitepress preset,
  ignored `.vitepress/`+CI+out-of-root files, skipped MDX with a
  warning, grouped/titled/ordered modules, explicit-config override.
- 3 `CourseRepoAdapterTests` added to `courses/tests.py`. Full Django
  suite runs in CI (`backend-tests.yml`, now installing PyYAML).
