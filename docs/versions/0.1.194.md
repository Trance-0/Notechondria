# 0.1.194 - GitHub sync: prune orphaned note assets

Fixes #28. Repeated `include_assets=true` pushes accumulate orphan files:
when a note is deleted client-side, its `assets/notes/<uuid>/…` subtree
keeps living in the remote tree (the push builds a delta on `base_tree`,
so it only ever adds/updates — it never removed the dead paths).

## What ships

- **`_orphan_asset_deletions(remote_tree, live_asset_uuids)`** — a pure
  helper that, given the recursive remote tree and the set of live note
  uuid hexes, returns Git-tree delete entries (`sha=None`, the Trees API
  delete form) for every `assets/notes/<uuid>/…` **blob** whose uuid is
  not live. Only note-asset blobs are ever targeted — notes, course
  files, the profile export, the avatar, and any hand-added repo files
  are never touched; `tree` entries are never emitted.
- **`commit_and_push(..., prune_asset_uuids=None)`** — when the set is
  supplied, it fetches the recursive base tree and appends the orphan
  deletions to the same tree POST, so pruning lands in the **same atomic
  commit** as the push (no extra commit, no separate round-trip). If the
  remote tree is `truncated` (very large repo), pruning is skipped and
  logged rather than acting on a partial listing.
- **`push_user_data(..., prune_orphans=False)`** — computes the live set
  as the creator's current, non-soft-deleted notes (exactly what the
  export materializes) and passes it down.
- **`POST /api/v1/creators/github/sync/push/`** accepts a `prune_orphans`
  flag (query string or JSON body, same truthy parsing as
  `include_assets`/`force`) and echoes it in the response. Defaults to
  false, so existing callers are unchanged.

## Verification

- `creators.tests.OrphanAssetPruneTests` — pure-function coverage: only
  dead-note blobs are deleted, live-note/avatar/notes files are kept,
  `tree` entries are never emitted, an empty live set prunes every
  note-asset blob (but not the avatar), and an all-live set prunes
  nothing. Each deletion is asserted to be a null-sha blob entry.
- The risky decision (which paths to delete) is a pure function so it is
  CI-unit-tested without HTTP; the atomic-commit wiring reuses the
  existing Git Data API flow from 0.1.189.
- Backend-only; `backend-tests.yml` is the authoritative run (no local
  Django on this host). `py_compile` clean.

Closes #28
