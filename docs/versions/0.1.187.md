# 0.1.187 - Fix Casdoor login: hash fragment leaked into redirect_uri

## Root cause (why login broke with zero logs)

`launchOAuth` built the OAuth `redirect_uri` as
`Uri.base.replace(queryParameters: {})` — which **keeps the URL
fragment**. Before hash routing the page URL had no fragment; since
0.1.179/0.1.186 the apps put `#/settings` (etc.) in the address bar — and
the sign-in button lives on the Settings tab. The authorize request
therefore carried `redirect_uri=…/portal/#/settings`, which fails
Casdoor's **exact-match** redirect validation. The IdP never redirected
back with a code, the backend was never called — hence no log anywhere.

## Fix

- `redirect_uri` is now `Uri.base.removeFragment().replace(queryParameters:
  {})` — the same clean value that is registered in the Casdoor app.
- The token exchange itself never sends redirect_uri (backend-side), so
  the authorize request was the only breakage point.

## Effective logging added to the pipeline

- Launch: `Casdoor sign-in starting … redirect_uri=<value> intent=<x>` —
  a mismatch is now visible in the debug log before the redirect.
- Callback: `Casdoor callback received … starting exchange` on `?code=`
  detection (exchange success/failure/link-challenge were already
  logged).

Shared mixin → all three apps pick the fix up in one build.
