# 0.1.160 - MCP agent enablement: gateway route fix, task parity, instructions, CLI batch

## Context

Owner priorities this round: make the Activity surface (calendar +
tasks) work ASAP, then enable AI agents to remote-test the app and
create/manage tasks for the user over MCP — with well-defined
instructions for every implemented function and a CLI path for batch
work. Mid-round the dev host crashed under a full-stack
`up --build`; the resource rules that came out of that are in
docs/AGENTS.md ("Host resource budget") and are now a standing
constraint.

## Bugs found and fixed

### 1. `/mcp/` unreachable through the Docker gateway

`deployment/docker/nginx/default.conf` proxied only `/api/`,
`/admin/`, `/static/`, `/media/` and the three app prefixes; Django
mounts the MCP server at `/mcp/` (no `/api/v1` prefix by design), so
every MCP call through the gateway 404'd at nginx while the backend
served it fine on the internal origin. This is very likely why "is
MCP even running?" was unanswerable. Added the `/mcp/` location block
(same proxy shape as `/api/`); documented the reverse-proxy
requirement in `docs/server/mcp.md`.

### 2. MCP-created planner events diverged from app-created ones

`backend/mcp/tools.py` `_create_event`/`_update_event` wrote raw ORM
rows, skipping `normalize_planner_event_window` (the REST create/PATCH
contract: bare-date events get a noon one-hour window; `event_date`
snaps to `starts_at`'s day). MCP responses also returned raw nulls
where REST returned the normalized window. Both tools now
`refresh_from_db()` + normalize after save. `update_event` also gained
the REST reopen behavior (`is_completed: false` clears
`completed_at`), which it silently lacked. Regression tests:
`test_create_event_normalizes_window_like_rest`,
`test_update_event_reopen_clears_completed_at`.

### 3. Misleading tool schemas

`create_event.starts_at/ends_at` were documented as "ISO time
(HH:MM:SS)" but the model fields are DateTimeFields — an agent
following the schema would fail. Now documented as full ISO 8601
datetimes everywhere (both servers).

## New capabilities

- **`seed_agent_user` management command** (creators): idempotent
  agent test identity + fresh `ntc_` key on stdout
  (`NOTECHONDRIA_API_KEY=...` greppable last line). Guarded by
  `DEBUG=True` or `ALLOW_AGENT_SEED=1`. 3 tests.
- **Baseline MCP `instructions`** on `initialize` in both servers
  (`backend/mcp/instructions.py` ≡
  `cli/notechondria_mcp/instructions.py`, byte-identical parity):
  data model, task/deadline semantics, common workflows, destructive-
  tool cautions, batch guidance. User `skill.md` appended under
  `## User skill.md` when present (previously it was the only
  content).
- **Tool description/schema upgrade** (both servers, planner cluster
  in full): create/update/delete/list event, `get_activity_week`
  (now with the app's `days` ∈ {3,7,30} range selector), calendar
  feeds (secret-iCal-URL gotcha), plus PERMANENT warnings on
  `empty_recycle_bin` / recoverability note on `delete_note`.
- **REST `planner-events/` GET extras** (backward-compatible,
  opt-in): `include_completed=1` and `limit=` so the CLI can mirror
  the in-backend `list_events` exactly. Defaults unchanged.
- **`notechondria-mcp batch`** (new `cli/notechondria_mcp/batch.py`):
  JSONL of `{"tool", "arguments"}` per line from file or stdin, one
  JSON result per line, continues past per-item errors
  (`--stop-on-error` to abort), `#` comments skipped, exit 0 only if
  all succeeded. This is the designated bulk path (syllabus imports
  etc.); the server instructions point agents to it. 3 tests.
