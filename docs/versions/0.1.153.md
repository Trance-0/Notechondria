# 0.1.153 - "Work offline" escape on the connection-error bar

## User report

When the backend is unreachable, the error bar persistently shows
"Couldn't reach the server. Check your connection and try again." with
only a Retry action — there was no clear way to stop the retries and
run the app purely on local storage.

## What changed

Added a **"Work offline"** button to the connection-error bar in all
three apps (editor `build_helpers.dart`, planner + portal
`app_shell.dart`). Tapping it calls the existing `_setOfflineMode(true)`,
which:

- persists `offline_mode = true`,
- re-runs `_loadInitialData`, whose offline branch renders from the
  local cache and clears the error message (so the bar disappears),
- and makes every subsequent boot skip remote fetches — the app runs
  purely on the local-storage module until the user turns the
  connection back on from Settings → Backend.

The button only shows while `offline_mode` is off (no point offering it
when already offline). The existing Retry + transient dismiss (X) are
kept. ARB: +1 key (`errorWorkOffline`, en/zh).

This pairs with 0.1.150's `friendlyError` (which produces the localized
"Couldn't reach the server" text): network failure now offers a real
escape, not just a retry loop.

## Verification

- `flutter analyze` — 0 errors across shared + all three apps (also
  confirms `_setOfflineMode` is reachable from each error bar).
- `flutter test` — shared suite + all three smoke tests pass.
- `flutter build web` — all three apps pass.

## Note (unrelated backend crash)

The reported backend crash was a Postgres **connection timeout** during
`migrate` (the DB addon was unreachable at deploy time) on the deployed
`0.1.150` image — an infrastructure issue, not a code/port change. No
new ports were opened by recent work; the backend still exposes only
`8000`. See the chat for the full diagnosis.
