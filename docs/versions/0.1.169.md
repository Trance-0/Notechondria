# 0.1.169 - Activity course (category) filter

## Context

Final activity-UI item from the owner batch: "on top of the activity
menu, use a filter to filter the events by course (category)."

## What changed (portal)

- `_ActivityPage` became a `StatefulWidget` holding `_courseFilter`
  (null = all courses). A new `_CourseFilterBar` sits above the calendar
  (a `filter_list` icon + a course dropdown built from the user's
  courses, de-duplicated by id, with an "All courses" entry). It hides
  itself when the user has no courses, and guards against a stale
  selection (e.g. an unsubscribed course) by falling back to "all".
- When a course is selected, the week grid, the vertical deadline
  board, and the deadline list are all filtered to events whose
  `course_id` matches (`_filterDays` / `_filterEvents`), so the whole
  surface narrows to one category.
- `app_shell` now passes the merged local+cloud `courses` list into the
  activity page (device-local list only when signed out).
- New l10n key `activityAllCourses` in the shared ARB + generated
  `AppLocalizations` (en + zh).

## Verification

- Interpolation-aware Dart brace balance passes on the edited files;
  both ARBs parse as JSON; no un-prefixed field references leaked into
  the new `State` class (checked by grep). Flutter build not run
  locally — `frontend-pages.yml` is the authority post-push. Follows
  0.1.168's lesson: the CI build is the only real gate for Dart, so this
  is pushed and watched.
