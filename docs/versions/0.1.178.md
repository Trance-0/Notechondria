# 0.1.178 - Calendar/course feature batch: foundations + modules + event colours

First slice of the 8-item calendar/course feature request. Backend
foundations (CI-tested) plus the two most visible, self-contained frontend
features. The interaction-heavy items (drag-to-reschedule, ctrl+scroll
zoom, offline-cache ownership) are scoped in TODO — they need a local
Flutter build to implement/validate safely.

## Backend foundations (migrations 0021 / courses 0007)

- **`Course.color_hue`** (0-359, nullable) — per-course accent hue. On
  `CourseSerializer`; writable via `CourseWriteSerializer` + the course
  `PATCH` (validated 0-359).
- **`Note.module`** — the module/section a note belongs to, set on
  git-import from the adapter's grouping (cv, dnn, …); on the note summary
  serializer.
- **`planner_event_payload`** now embeds the event's `course`
  `{id,title,slug,color_hue}`. (Event write already accepts `course_id`.)

## Frontend

- **#4 — imported-course modules.** The course view groups notes by the
  backend `module` field (so Veronica-7 shows cv / dnn / fundamentals /
  llm / transformer-era) instead of fanning every note into its own
  module, and no longer fabricates objectives / assignments / "discussion
  board" placeholder text (rendered only when a module declares them).
- **#6 (core) — HSV event colours.** Calendar tiles are coloured so each
  channel means something: **hue = course** (explicit `color_hue` else a
  stable per-id hue), **saturation = importance** (difficulty 1-5),
  **value = theme** (bright in light, muted in dark). Session/feed tiles
  keep their hues but adapt value.

## Verification

- Backend: `py_compile`; new `CourseHueAndModuleTests` (hue set/validate,
  git-import populates `module`, event payload carries course hue) — Django
  CI green on the foundations commit.
- Frontend: ARB valid, bracket-balanced; Pages build is the Dart gate —
  `frontend-pages` built green (the HSV colour refactor + module grouping
  compile).

> Note: `frontend-pages` and `docs-pages` share the `gh-pages-publish`
> concurrency group and both trigger on `VERSION`, so a version-bump commit
> races them and one gets `cancelled` (not failed). A docs-only follow-up
> commit (no `VERSION` change) lets `docs-pages` publish unopposed.
