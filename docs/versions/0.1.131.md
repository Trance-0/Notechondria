# 0.1.131 - remove legacy "Inbox" categories (duplicate-Inbox bug)

## User request

Fix the existing backend database: remove every category named "Inbox"
that some historical versions auto-created. The "Inbox" the user sees
should only ever be the synthetic uncategorized bucket (notes with
`course_id IS NULL`, labelled by `Creator.uncategorized_folder_name`,
default "Inbox") — never a real `Course` row. Fix the bug where in
some cases an Inbox is auto-created or shows in the UI alongside the
default one (a real "Inbox" category and the synthetic bucket
rendering at the same time).

## Root cause

Pre-0.1.120 builds created a real `Course` row titled "Inbox"
(carrying the now-removed `is_default=True`) per account. 0.1.120
retired that concept — the uncategorized bucket became a purely
client-side render of `course_id IS NULL` notes — but **legacy "Inbox"
`Course` rows linger in older databases**, and the editor sidebar
renders such a row as a second "Inbox" next to the synthetic bucket.
No current code path creates an Inbox `Course` (the 0.1.101
`seed_welcome_note` makes a Note with `course_id=None`, not a course;
the local starter stopped creating one in 0.1.120). The 0.1.125
migration *prompt* let users dismiss it and keep the duplicate
indefinitely — that is why the bug persisted.

## What changed

### Backend — data cleanup command

- New `backend/courses/management/commands/cleanup_inbox_courses.py`:
  deletes every `Course` whose title is "Inbox" (case-insensitive) and
  that belongs to a creator (`creator_id IS NOT NULL` — never touches
  ownerless/public-catalog rows). Notes are re-parented to
  `course_id = NULL` first (explicit `UPDATE` for an exact moved-count;
  `Note.course_id` is `on_delete=SET_NULL` so nothing is ever lost),
  then the courses are deleted. Idempotent; `--dry-run` and `--limit N`
  flags; per-course heartbeat.
- Runbook added at `docs/operations/inbox_cleanup.md`.

### Frontend (editor) — silent auto-migration

- `editor_app/lib/core/inbox_migration.dart`: replaced the dismissable
  once-per-session prompt with **silent auto-migration**
  (`_autoMigrateLegacyInbox`). When a signed-in session loads with an
  owned "Inbox" category, its notes are reparented to the uncategorized
  bucket (cloud: `deleteCourse` → backend `SET_NULL`; local: drop
  `course_id` from drafts and remove the local course) and the category
  is deleted, surfaced as a SnackBar. Removed the now-dead
  remove-vs-rename dialog, the `_InboxMigrationDecision` class, and the
  `moveToCategory` branch; `_runInboxMigration` collapsed to
  `_mergeInboxIntoUncategorized`. Runs once per session and self-heals
  on the next boot if a pass failed offline.

## Verification

- Backend: new `courses/tests.py::CleanupInboxCoursesCommandTests`
  (delete + reparent, case-insensitive match, `--dry-run` no-op,
  idempotent, ignores ownerless rows, `--limit`) — 6/6 pass. Full
  `manage.py test` suite passes under `settings_test`.
- Frontend: editor `flutter analyze` 0 errors; `test/smoke_test.dart`
  passes; `flutter build web --release --base-href /Notechondria/editor/
  --no-web-resources-cdn` passes.

## Operator action required

Run the cleanup command once against the live database to remove the
legacy rows from existing accounts:

```bash
python manage.py cleanup_inbox_courses --dry-run   # audit first
python manage.py cleanup_inbox_courses             # apply
```

The frontend auto-migration also cleans a signed-in user's own legacy
Inbox on next load, but the command is the authoritative sweep.
