# 0.1.122 - click-run database and R2 backup scripts

User directive:

> in scripts folder of the project root, add python scripts to auto
> download and backup the database to ./scripts/db_backup/<backup_time>.tar
> or user selected dir ... and also create the similar version independent
> scripts for cloudflare storages. add restore scripts for both db and
> remote storage space. (4 scripts in total)

## What changed

Added four standalone Python scripts under repo-root `scripts/`:

- `scripts/backup_database.py`
- `scripts/restore_database.py`
- `scripts/backup_cloudflare_r2.py`
- `scripts/restore_cloudflare_r2.py`

The database scripts read root `.env`, prefer `DATABASE_URL`, and fall
back to the `POSTGRE_*` variables. Backups are PostgreSQL tar dumps
written to `scripts/db_backup/<YYYYmmdd-HHMMSS>.tar` unless the operator
sets `USER_SELECTED_BACKUP_DIR`.

The database restore script restores the newest tar in the backup
directory by default, or the exact `RESTORE_FILE` set inside the script.
It prompts for `RESTORE_DATABASE` before applying `pg_restore`.

The Cloudflare R2 scripts read root `.env` R2 credentials and use
Python stdlib SigV4 signing against Cloudflare's S3 API, so they do not
need boto3 or AWS CLI. R2 backups are version-independent tar archives
written to `scripts/r2_backup/<YYYYmmdd-HHMMSS>.tar`; each archive has a
`manifest.json` plus opaque object payloads under `objects/`.

The R2 restore script overwrites matching object keys by default and
leaves extra remote objects alone. The operator can set
`DELETE_REMOTE_OBJECTS_NOT_IN_BACKUP = True` inside the script for an
exact replacement restore.
