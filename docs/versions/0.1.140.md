# 0.1.140 - i18n Phase 1b: editor settings + debug-log menu translated

## User request

The language switch didn't visibly change the UI; fix it. Also localize
the debug-log **menu** (chrome) — but not the log output lines
themselves.

## Diagnosis

The 0.1.133 switch mechanism was working (editor `MaterialApp` had the
delegates + `locale`), but only ~3 strings were translated, so switching
to Chinese looked like nothing changed. The fix is to actually translate
the visible surfaces. The shared debug-log card also needed
`AppLocalizations` available in planner/portal (they lacked the
delegate).

## What changed

### Delegates in all three apps

- planner + portal `MaterialApp` now declare
  `localizationsDelegates: AppLocalizations.localizationsDelegates` +
  `supportedLocales` (editor already had them). They follow the device
  locale for now (a Language *setting* for them is a later phase); this
  lets the shared widgets localize everywhere.

### Translated surfaces (en + zh)

- Shared `DebugLogCard` menu chrome: "Copy logs", "Filters",
  "All sources", the per-level filter chips (Error/Warning/Info/Debug),
  the filter summary, and the empty states. The **log rows and the
  terminal command I/O stay English** (greppable structured output /
  command syntax), per the request to localize the menu, not the log
  output.
- Editor settings: the settings-menu tile titles + static subtitles
  (Editor settings, View tutorial, Backend settings, Local data,
  Recycle bin, Developer), all eight settings subpage app-bar titles,
  the Editor-settings rows (Default editor mode / Theme preset / Theme
  mode), the immediate-save caption, and the Debug-log card title.

### Catalog

- `app_en.arb` / `app_zh.arb` grew from 7 to ~30 keys (common buttons,
  settings chrome, debug-log menu, log-level names). Regenerated the
  committed `AppLocalizations`.

Switching the editor's Language now visibly re-renders the whole
settings surface and the debug-log menu into 简体中文.

## Verification

- New `debug_log_l10n_test.dart`: the card renders English chrome under
  `en` and Chinese chrome under `zh` (proves the delegate wiring + the
  switch), plus a direct `AppLocalizations` zh-key resolution test.
- `flutter analyze` — 0 errors across `notechondria_shared` and all
  three apps.
- `flutter test` — shared suite + all three smoke tests pass.
- `flutter build web` passes for all three apps.

## Scope / follow-up

Still hardcoded English (later i18n phases, tracked in `docs/TODO.md`):
the rest of the editor (note editor, learner view, dialogs), planner +
portal app strings, the other shared widgets (onboarding, what's-new,
install banner, auth dialogs), and a Language *setting* for
planner/portal. The `AppPreferencesCard` "Language"/"View tutorial"
rows planner uses are still English.
