> continue working on refining the Editor app. For this time, do all

## What changed

### Debug log window

- `DebugLogCard` now builds a second chip row from structured
  `DebugLogEntry.source` values, so the user can filter visible rows
  by module/process in addition to severity.
- Editor module callback logging now uses `EditorLogSink` instead of
  `ValueChanged<String>`, carrying `source`, `level`, `message`, and
  optional `durationMs`.
- Learner/editor/attachment events now arrive with concrete sources
  such as `Editor.UI/open_editor`,
  `Editor.UI/editor.save`, and
  `Editor.Sync.Notes/attachment.queue`.
- Signed-out first-run local drafts now render in the Learner page even
  when the cloud/public scope is selected, restoring the offline starter
  note path covered by the smoke test.

This completes the Editor-side TODO item to migrate callback-routed
logs away from empty-source Info rows.

### Portable archive goal

`docs/client/editor_app.md` now states the Editor app's compatibility
principle: Notechondria should not make an app database the long-term
archive. The target archive shape is GitHub-flavored Markdown for prose,
JSON/frontmatter for structured metadata, and media as normal files
next to entries.

The doc also records that Apple Journal, GitJournal, Joplin, Obsidian,
Day One, ZIP, JSONL, Git/WebDAV/S3/R2, and local folder flows should
be adapters around the same Markdown/JSON/media format.

### Apple Journal import conflict

The requested Apple Journal import has one unresolved implementation
choice: the deployed Flutter web app can reliably import a selected ZIP,
but it cannot recursively read an arbitrary user-selected folder with
the current `file_selector` flow. `docs/TODO.md` now tracks the
proposed first phase:

- Apple Journal export ZIP -> local categories/drafts only.
- Cloud sync stays paused until the user manually pushes.
- A later desktop-only `dart:io` path can support selected folders.
