# 0.1.179 - Portal URL routing: unique, shareable addresses for every surface

The long-standing routing gap: the portal was a single-root-route app
(`MaterialApp(home: AppShell)`) — tabs, courses, and notes all lived at `/`,
so nothing was linkable. This round gives every surface a unique URL under
Flutter web's hash strategy (works on GitHub Pages with no server rewrites).

## URL map

| URL | Surface |
| --- | --- |
| `#/` | Front page |
| `#/notes` | Notes (learner) tab |
| `#/courses` | Course list |
| `#/courses/<slug>` | Course detail (cold-start deep link opens the course) |
| `#/activity` | Activity/calendar tab |
| `#/settings` | Settings |
| `#/note/<uuid>` | **Routed note page** — shareable per-note URL |

## How it works

- **`MaterialApp` routing** (`onGenerateRoute` + `onGenerateInitialRoutes`
  replace `home:`): tab and `/courses/<slug>` routes resolve to the shell
  (`initialIndex` / `initialCourseSlug`); `/note/<uuid>` builds a
  `_NoteRoutePage`. A cold-start note deep link gets the shell stacked
  underneath so Back lands in the app.
- **In-session URL sync**: tab switches, opening a course, and selecting a
  note call `url_strategy.replaceBrowserPath(...)` (web:
  `history.replaceState` on the hash; no reload, no history spam) so the
  address bar always identifies what's on screen.
- **Routed note page** (`components/note_route_page.dart`): in-session
  pushes arrive preloaded (`Navigator.pushNamed('/note/<uuid>')` from the
  viewer flow — browser Back closes the note); cold-start fetches by uuid
  via the new `client.getNoteDetailByUuid` (`/notes/uuid/<uuid>/`).
  In-course relative links keep working — each hop pushes another
  `/note/<uuid>` route (shared top-level resolver `_matchNoteLinkTarget`).
  Local drafts (no server uuid) keep the in-place dialog.
- **Access policy (backend)**: `can_access_note` now grants read access to
  **active subscribers of the note's course** in addition to
  owner-or-public. So a shared note URL works: anonymously for public
  notes; with sign-in for owned *and subscribed private* content. Write
  access stays owner-only.

## Verification

- Backend: `NoteUrlAccessPolicyTests` — public-by-uuid anonymous read,
  private refused anonymously, active subscriber reads (but `can_edit` is
  false), inactive subscription refused, unrelated user refused. Django CI
  is the gate.
- Frontend: bracket-balanced, no stale refs; Pages CI build is the Dart
  gate (this round's routing rewrite compiles there).

## Notes / follow-ups

- The portal deliberately does not persist auth tokens client-side, so a
  cold-start deep link is anonymous until sign-in; private-note URLs show a
  "sign in from the app" hint. Token persistence is a separate decision
  (tracked with offline-cache ownership, #7 in TODO).
- Editor/planner apps keep their old single-route shells — porting this
  routing pattern to them is TODO.
