# 0.1.201 - Local folder mode in the editor

**Owner request:** add an option in the login window that checks for a
qualified Chrome and, when qualified, uses a local folder as a pure local
file backend with every feature.

This round lands Phase 2 of the design
([`development/local_folder_mode.md`](../development/local_folder_mode.md),
section 9.1). **The editor now shows the option.** The planner and the
portal do not yet; they get it in Phase 3.

## What changed for users

- Editor, Settings, signed out: a new "Use a local folder (no account)"
  button under the sign-in buttons, with a "Remember this folder on this
  browser" checkbox.
- On desktop Chromium browsers (Chrome, Edge) over https or
  `http://127.0.0.1`, the button opens the folder picker. The chosen
  folder becomes the editor's storage: notes are Markdown files under
  `notes/` with a `.meta.json` sidecar, and categories, trash, version
  history, snapshots, attachments, covers, the avatar, writing sessions,
  search, the front page, and the heatmap are files in the same folder.
  The page answers every API call itself, so no note data goes to the
  Notechondria server. The one exception is "Check for updates", which
  asks the saved server for its version and sends no token.
- Notes the browser had stored locally move into the folder when it is
  connected. The browser keeps recoverable copies in its local recycle bin
  for 30 days.
- With "Remember this folder" checked, a reload reopens the folder. When
  the browser drops the folder permission, a reconnect view replaces the
  editor until the user grants it again.
- Firefox, Safari, mobile browsers, and plain http pages show the button
  disabled with the reason, for example: "Local folder mode unavailable:
  Shared.LocalFolder/qualify — this browser does not provide
  window.showDirectoryPicker (File System Access API). Firefox and Safari
  do not offer it."

## What landed in code

- `notechondria_shared`: content routes for attachments, covers, the
  avatar, history, snapshots, restore, and writing sessions; a port of the
  backend's `note_search_score`; the front page and heatmap from the
  folder; `folderAwareImageProvider` and `folderAwareSvg` for
  `nc-folder:` image URLs; 35 new strings in English and Chinese.
- `editor_app`: `core/local_folder_connect.dart` (the `local_folder`
  startup step, the folder session, the connect-time move of local notes,
  the verification rescan, the reconnect view, and the status card);
  cloud-only Settings controls gated in folder mode; folder-aware images;
  and the visible option.
- Also in this range (loop 2a): index-backed note lookups, `index.json`
  kept current across reloads and scans, and the phase 1 review fixes.
- Final review fixes (`.agents/tasks/review-phase2-final.json`): F1,
  `StorageModeClient` answers any request that still carries the folder
  token outside folder mode with a 503 in the page, so a flow that
  captured the token before Disconnect sends nothing to the cloud host;
  F2, attachment names are deduplicated case-insensitively, so
  `photo.png` after `Photo.png` is stored as `photo-2.png` instead of
  overwriting it on APFS or NTFS. N8: the Casdoor organization login link
  is hidden in folder mode. The other findings are in docs/TODO.md,
  "Deferred from the 0.1.201 final review".
