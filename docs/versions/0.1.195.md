# 0.1.195 - Editor Settings: "Settings" no longer shown twice

Directly-reported UI bug: on the editor's Settings screen the word
"Settings" appeared twice.

## Cause

The shell's navigation already labels the destination "Settings"
(`l10n.navSettings` — the sidebar item in the wide layout, the drawer
item in compact). The Settings **page body** *also* rendered a
`Text('Settings')` headline at the top of its `ListView`. On the wide
layout both were on screen at once (sidebar label + body headline), so
the word showed twice.

This was the only main page that duplicated its nav label as a body
title — Notes / Course / Activity render no such headline and rely on the
nav label alone.

## Fix

Remove the redundant `Text('Settings')` headline from
`editor_app/lib/modules/settings.dart` (a comment there records why). The
descriptive intro line ("Manage your account, preferences, and local
data…") stays as the page's opening text, and the navigation label
remains the single "Settings" on screen — matching the other tabs.
Planner and portal already showed "Settings" only once (no body
headline), so they are unchanged.

## Verification

Frontend-only, editor. Bracket-balanced; confirmed no `Text('Settings')`
headline remains in the editor settings body and that Notes/Course/
Activity carry no equivalent body title. `flutter build web` + smoke
test via `frontend-pages.yml`; verify the deployed editor bundle version
after the Pages build.
