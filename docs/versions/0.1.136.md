# 0.1.136 - Local-data storage visualization (editor) + handshake storage field

## User request

Add a visualization in the Local data settings menu (cross-app) showing
which backend the app is using, a memory-usage decomposition, memory
left, the backend storage architecture name, and suggestions if memory
runs low and a migration/backup is needed.

## What changed

This lands the backend field + the shared widget + the editor wiring
(the first app). Planner and portal reuse the shared `StorageUsageCard`
in a follow-up (they have divergent settings shells).

### Backend — expose the storage architecture

- `notechondria/api_views.py`: the `/api/v1/handshake/` response now
  includes a `storage` object — `{"backend": "cloudflare-r2" |
  "local-disk", "label": "Cloudflare R2" | "Local disk"}` — derived
  from `STORAGES['default']['BACKEND']`. Tests added
  (`HandshakeEndpointTests`: shape + both branches via
  `override_settings`).

### Shared package — the visualization widget

- New `StorageUsageCard` (`lib/src/components/storage_usage_card.dart`):
  renders the backend host + backend storage arch, total local data
  used, the browser storage quota + free space (web), a per-bucket
  breakdown with proportion bars, and low-storage suggestions
  (clear cache / push to cloud / export a backup) when usage crosses
  thresholds.
- New `readStorageEstimate()` conditional-import helper
  (`lib/src/utils/storage_estimate.dart` + `_web.dart`): returns the
  origin's `(usage, quota)` bytes from the browser StorageManager
  (`navigator.storage.estimate()`), `(null, null)` off the web. Exported
  `StorageUsageCard` from the barrel.

### Editor — wire it into the Local data subpage

- `HandshakeResult` gained a `storageLabel`, parsed from the handshake
  `storage.label`; `verifyHandshake` moved onto the `NotechondriaClient`
  interface.
- `_LocalAppStore.bucketSizes()` measures the persisted UTF-8 byte size
  of each local bucket (drafts / categories / cached server data /
  recycle bin / logs / settings / stats; the session/token key is
  excluded).
- A `_StorageUsageSection` at the top of the editor's Local data subpage
  gathers the bucket sizes, attachment bytes
  (`LocalAttachmentStore.totalBytes()`), and the storage-arch label
  (via a new `onProbeStorageArch` handshake probe) and renders the
  shared `StorageUsageCard`.

## Verification

- Backend: `HandshakeEndpointTests` (4 incl. storage shape + both
  branches) pass; full `manage.py test` suite passes.
- Frontend: `flutter analyze` — 0 errors in `notechondria_shared` and
  `editor_app`; editor `test/smoke_test.dart` passes; `flutter build
  web` passes for all three apps (planner/portal still build against
  the updated shared package).

## Notes / follow-up

- The browser quota line shows only on web (the StorageManager API);
  native builds show "not reported by this platform".
- Bucket sizes are the JSON byte footprint in `SharedPreferences`
  (localStorage on web); attachment bytes come from IndexedDB. The
  browser quota covers both plus other origin storage.
- Planner and portal: add the same `StorageUsageCard` to their Local
  data UIs (tracked in `docs/TODO.md`).
