# 0.1.189 - GitHub sync: no more silent overwrites (atomic push + conflict gate)

First round worked from the [GitHub Issues board](https://github.com/Trance-0/Notechondria/issues),
ordered by severity. Top of the list was a **silent data-loss** bug.

## #27 — Push-side conflict resolution (data loss)

`github_sync.commit_and_push` walked the file list and issued one
Contents API `PUT` per path, each overwriting the remote blob with a sha
read moments earlier. Two consequences:

- **Silent data loss.** Anything committed since the previous sync —
  a second device, or an edit made directly on GitHub — was discarded
  with no warning.
- **Non-atomic and slow.** One request per file meant a partial push if
  anything failed mid-loop, and N sequential round-trips (the same
  pathology fixed for *course* sync in 0.1.176; profile sync never got
  the treatment).

Rewritten to a single **Git Data API** commit — blobs → tree on
`base_tree` → commit → ref update — with a **conflict gate**: the branch
head is compared against `GithubIntegration.last_push_sha`, and if the
remote moved, the push raises `GithubSyncConflict` **instead of
overwriting**. A blank `last_push_sha` (first-ever push) has nothing to
compare and proceeds.

- `POST integrations/github/push/` returns **409** with
  `{"conflict": true}` and an explanatory message, rather than a generic
  400 — the request was valid; the world moved.
- `?force=1` (or `{"force": true}`) is the deliberate overwrite path,
  threaded through `push_user_data(force=…)`.
- Blobs are uploaded base64 and referenced by sha, so attachment bytes
  survive intact (inline tree `content` would be UTF-8 only).
- A tree identical to the published one produces **no commit at all**.

## #8 — Multi-repo per user (verified already satisfied)

`GithubIntegration.repo_full_name` is used *only* by profile-sync and its
API/MCP surface. Course sync resolves its target from `Course.git_repo`
and pushes with the installation token, which covers every repo the App
was installed on — so each course already pushes to its own repository.
Closed with that evidence rather than re-implementing it.

## Verification

Full Django suite in the Docker harness: **254 tests OK**. New
`GithubSyncPushConflictTests` covers: conflict raised (and **nothing
written**) when the remote moved, `force=True` overwriting, first-ever
push proceeding, 12 files producing exactly one tree + one commit + one
ref update, and an unchanged tree producing no commit.

Closes #27. Closes #8.
