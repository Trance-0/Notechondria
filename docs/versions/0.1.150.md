# 0.1.150 - i18n: friendly, localized UI-level error warnings

## User request

Add translations for UI-level warnings (not the debug window) — e.g.
"client failed to fetch" and similar raw error strings shown to the
user.

## Problem

When a request fails, the frontend surfaces the **raw** stringified
exception — most visibly in the main error bar
(`_errorMessage = errors.first`). Offline, that reads
`ClientException: Failed to fetch, uri=…`; a 5xx shows a raw HTTP line.
Fine for the debug log, gibberish for users (and untranslated).

## What changed

- **New shared helper** `friendlyError(AppLocalizations l10n, Object?
  rawError)` (`notechondria_shared/lib/src/utils/friendly_error.dart`,
  exported from the barrel). It classifies the raw error and returns a
  clean **localized** sentence:
  - network unreachable (Failed to fetch / `ClientException` /
    `SocketException` / connection refused-reset-closed / `XMLHttpRequest`
    / `ERR_*`) → `errorNetwork`
  - timeouts → `errorTimeout`
  - 5xx-shaped failures → `errorServer`
  - anything else (typically an already-human backend message like
    "Title is required") **passes through unchanged** — we never hide a
    useful server message behind a generic one. The `Exception: ` prefix
    is stripped.
- **Wired into the main error bar of all three apps** (editor
  `build_helpers.dart`, planner + portal `app_shell.dart`): the bar now
  shows `friendlyError(l10n, _errorMessage!)`. While there, localized
  the planner/portal error-bar Retry/Dismiss (the editor's were already
  done in 0.1.141).
- ARB: +3 keys (`errorNetwork`, `errorTimeout`, `errorServer`).

## Verification

- New `friendly_error_test.dart` (6 tests): fetch/socket → network,
  timeout → timeout, 5xx → server, human messages pass through, empty →
  network, en + zh.
- `flutter analyze` — 0 errors across shared + all three apps.
- `flutter test` — shared suite (45) passes.
- `flutter build web` — all three apps pass.

## Scope / follow-up

This covers the highest-traffic surface (the persistent error bar). The
many per-action SnackBars that still show `error.toString()` (note save,
attachment upload, cover image, etc.) can adopt `friendlyError(l10n, …)`
incrementally — the helper is now available app-wide. Still open in
`docs/TODO.md`: the version-update notification feature and
`mcp_skill_section.dart`.
