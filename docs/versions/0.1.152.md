# 0.1.152 - Version-update notification banner (frontend)

## Context

Second half of the version-update feature (handshake-compare approach,
owner-confirmed). 0.1.151 added the backend `min_frontend_version`
field; this round adds the frontend banner that consumes it, across all
three apps.

## What changed

### Shared (`notechondria_shared`)

- **`utils/version_status.dart`**: `compareSemver(a, b)` (dotted-numeric,
  pre-release/build suffixes ignored, non-numeric → incomparable),
  `AppVersionStatus { upToDate, updateAvailable, deploying, unsupported }`,
  `computeVersionStatus(...)`, and a `BackendVersionInfo` carrier.
  - backend `version` > frontend → **updateAvailable** (new deploy live,
    browser still on the cached bundle → refresh)
  - backend `version` < frontend → **deploying** (rollout in progress;
    new bundle served, backend container not flipped yet)
  - frontend < `min_frontend_version` → **unsupported** (wins over the
    version compare)
  - equal / incomparable → **upToDate** (no banner)
- **`components/version_update_banner.dart`** `VersionUpdateBanner`:
  self-contained — owns a periodic probe (default 15 min) + a
  post-first-frame check, renders a localized top-of-screen banner with
  a Refresh action (hard browser reload via the web url-strategy), or
  nothing when current / offline. Soft banners are dismissible; the
  unsupported one isn't. Returns `SizedBox.shrink()` otherwise.
- `browserReload()` added to the shared web/stub url-strategy.
- ARB +4 keys (`versionUpdateAvailable`, `versionDeploying`,
  `versionUnsupported`, `versionRefresh`).

### Per-app wiring (editor / planner / portal)

- `HandshakeResult` gained `minFrontendVersion`, parsed from the
  handshake `min_frontend_version` in each `verifyHandshake`.
- A `_probeBackendVersion()` returns `BackendVersionInfo?` (null when
  unreachable) by calling `verifyHandshake(apiBaseUrl)`.
- `VersionUpdateBanner(frontendVersion: _kAppVersion, probe:
  _probeBackendVersion)` is hosted at the top of each app's scaffold
  body (above the error bar).

## How it behaves

On boot + every 15 min, each app probes the handshake. If the backend
reports a newer version than the running build, the user sees a
localized "A new version is available — refresh to update" bar; mid
deploy (backend behind the served bundle) shows "rolling out"; a build
below `MIN_FRONTEND_VERSION` shows a non-dismissible "no longer
supported — refresh". Offline → nothing (the probe returns null).
Designed to also back future mobile update prompts.
