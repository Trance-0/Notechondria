# 0.1.181 - Now-line, working ctrl+scroll zoom, event↔course binding

Portal activity view (horizontal/wide calendar), from the owner's report.

## Red current-time indicator

Google-Calendar-style **red now-line** across today's column (dot + 2px
bar, repainted every minute) and a **red HH:MM readout on the hour axis**
aligned to the line (48px header offset accounted for).

## Ctrl+scroll zoom — root cause

The Flutter-side handler existed since 0.1.163 (`Ctrl/⌘ + wheel →
_hourHeight zoom`), but on the web the **browser's page-zoom hijacks
ctrl+wheel before Flutter sees it**. Fixed in `web/index.html`:
`wheel` listener with `{passive:false}` calls `preventDefault()` when
`ctrlKey/metaKey` is held, so the in-app time-axis zoom now receives the
gesture. (The +/- zoom buttons keep working as before.)

## Event ↔ course (category) binding

- **Create dialog** (FAB, month grid, drag-to-draw): new "Course
  (project)" dropdown — default **Inbox (uncategorized)** = null, as
  specified. `courseId` threads through `onCreatePlannerEvent` into both
  the local-event and cloud payloads. (Previously the cloud path silently
  bound new events to whatever course happened to be selected in the
  Course tab — now it's always the explicit picker value.)
- **Edit dialog** (hold-to-edit): same dropdown, prefilled from the
  event; stale bindings fall back to Inbox; `changes['course_id']` PATCHes
  through (backend already applied it).
- **Details dialog**: now shows the event's course and importance label
  alongside the time — not just the time range.
- The course **filter bar + settings (edit) button** above the calendar
  are unchanged from 0.1.180 and render whenever the account has ≥1
  course; if they're absent on a device, it's a stale PWA bundle — accept
  the "new version" reload toast or hard-refresh.

## Verification

Bracket-balance + typedef-consistency checks locally; Pages CI is the
Dart gate. Backend untouched (event PATCH already handled `course_id`).
