# 0.1.202 - Local folder mode in the planner and portal

**Owner request:** add an option in the login window that checks for a
qualified Chrome and, when qualified, uses a local folder as a pure local
file backend with every feature.

This round lands Phase 3 of the design
([`development/local_folder_mode.md`](../development/local_folder_mode.md),
section 9.1). **The planner and the portal now show the option**, so all
three apps offer it. The editor has had it since 0.1.201.

## What changed for users

- Planner and portal, Settings, signed out: "Use a local folder (no
  account)" with the "Remember this folder on this browser" checkbox, the
  same option the editor shows.
- On desktop Chromium browsers (Chrome, Edge) over https or
  `http://127.0.0.1`, the chosen folder becomes the app's storage. Planner
  events with their completion state are in `planner/events.json`;
  imported calendars are in `planner/feeds.json`, with the calendar text
  in `planner/feeds/<id>.ics`. The week view and the deadlines are built
  from these files. Notes and courses use the same files as the editor.
  The page answers every API call itself, so no note or planner data goes
  to the Notechondria server.
- Import iCal in the planner saves the calendar into the folder.
- Courses, planner events, and imported calendars the browser stored
  before the folder was chosen move into the folder once, when it is
  connected. The browser keeps recovery copies for 30 days.
- In the portal, a link to a folder note (`#/note/<uuid>`) opens the
  folder first and then the note. While the folder waits for a pick or a
  permission, the page shows the reconnect view.
- Firefox, Safari, mobile browsers, and plain http pages show the option
  disabled with the reason, as in the editor.

## What landed in code

- `notechondria_shared`: folder routes for planner events (create with a
  `client_local_id` upsert, edit, completion), the activity week and
  deadlines, and calendar feeds (import, URL download with a 5 s bound,
  refresh, delete); the front page's upcoming events from the folder
  (336f24e4, fa6d92ab).
- `planner_app`: `core/local_folder_connect.dart` and
  `core/local_folder_push.dart` (the folder session, the connect-time
  push, the reconnect view, the status card), the calendar import's folder
  path, folder-aware images, and the visible option (95b0e013, 9bbf1a77).
- `portal_app`: `core/local_folder_connect.dart`, the cloud-only gates in
  `core/build_page.dart`, the reconnect view in `_NoteRoutePage`, the
  connect-time event push, and the visible option (44a3ed8a, ced339a4).
- `portal_app` final review fixes: the connect-time push now sends a
  local event's repeat rule (`recurrence_freq`, `recurrence_interval`,
  `recurrence_end_date`, `recurrence_count`, each only when set), so a
  weekly event stays weekly in the folder (F1), and it writes the recovery
  list before it removes the pushed events from the browser list, as the
  planner does (N7). The portal 7.1 smoke check now pushes a weekly event.
- Deferred items: 835ceeb2 and 345b7fdd, now in
  `docs/development/local_folder_mode/deferred.md`.
