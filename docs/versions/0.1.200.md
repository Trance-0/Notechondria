# 0.1.200 - Local folder mode: foundation (option not shown yet)

**Owner request:** add an option in the login window that checks for a
qualified Chrome and, when qualified, uses a local folder as a pure local
file backend with every feature; the frontend reads and renders the
content locally and acts only as a dashboard for local services.

This round lands Phase 1 of the approved design
([`development/local_folder_mode.md`](../development/local_folder_mode.md),
section 9.1). **Nothing changes for users yet:** no app shows the option,
and no app reads the folder storage key. The editor shows it at the end of
Phase 2, the planner and portal at the end of Phase 3.

## What landed

All under `frontend/notechondria_shared/lib/src/`:

- **Storage core** (`local_folder/`, Phase 1a): the File System Access
  folder (web, in-memory, and native stub), Web Locks wrapper,
  qualification probe, handle store, pick flow, controller and its
  states, write-ahead journal with roll-forward, folder layout, index and
  scans, note codec, snapshots, and the secret denylist.
- **In-page backend:** `LocalFolderTransport` (JSON and multipart
  decode, the `opening` hold, 503 answers per folder state, 8 s read and
  7 s write deadlines measured from request start), `StorageModeClient`
  (folder mode answers every request in the page; the only exception is
  a bare "Check for updates" handshake to the saved cloud URL), the
  router with its 501 and 404 fallbacks, and handlers for the handshake,
  ping, settings (per-device keys dropped), session, logout, Casdoor
  config, courses (with the chunked delete), notes, and trash (with the
  empty-trash cascade).
- **Widgets:** the `AuthHub.localFolderOption` slot,
  `LocalFolderSignInOption`, `LocalFolderStatusCard` (folder counts and
  bytes), `LocalFolderReconnectView`, and `LocalFolderChangeBanner`.
- **Plumbing:** `runGuardedApp(prepare:)`; the startup budget skips
  requests answered in the page; `pingBackend(client:)`; the session
  mixin's `localFolder` getter, `disconnectFolder()`, folder session
  messages, and `cloudOnly(...)` / `cloudOnlyAction(...)` gates.

## Behavior-preserving app changes

- The 8 multipart uploads (avatar, attachments, covers) now go through the
  app's injected client (`_httpClient.send(request)`) instead of
  `request.send()`, which created its own client. Same requests, same
  server.
- Each shell implements `localFolder => null`. The GitHub sync card
  builder and the admin template-course restore are wrapped in
  `cloudOnly(...)` / `cloudOnlyAction(...)`, which change nothing while
  `localFolder` is null.

## Contract checks

`frontend/notechondria_shared/test/fixtures/api_v1/` holds 21 hand-written
backend answers, each naming its serializer in `_source`. The shared
tests compare the folder's answers with them, and the new
`backend/notes/test_api_contract.py` compares the Django views with them
in `backend-tests` and uploads the live answers as the
`contract-responses` artifact.
