# 0.1.137 - cleanup_inbox_courses --include-ownerless + live DB sweep

## User request

Run the Inbox DB fix on the live database from this local session (not
a remote Docker container).

## What happened

Ran `cleanup_inbox_courses` against the live Postgres from the local
machine (`DATABASE_URL` from repo-root `.env`,
`DJANGO_SETTINGS_MODULE=notechondria.settings`). The owned-only sweep
found nothing, but a read-only audit turned up **one orphaned
ownerless** `Inbox` `Course` (`id=19`, `slug=inbox-7`, `creator_id`
NULL, 0 notes, **1 subscription**) — the leftover that rendered as a
duplicate "Inbox" category for the subscriber. The command's default
filter skips ownerless rows for safety, so:

## What changed

- `backend/courses/management/commands/cleanup_inbox_courses.py`: added
  an `--include-ownerless` flag that also targets `creator_id IS NULL`
  "Inbox" rows (a creator-deleted placeholder can still carry
  subscriptions and show as a duplicate Inbox). Default behavior
  unchanged (owned rows only).
- `backend/courses/tests.py`: split the old "ignores ownerless"
  assertion into a default-skips test + a new
  `--include-ownerless` removes-orphan test (7 tests total, all pass).
- `docs/operations/inbox_cleanup.md`: documented the flag and the
  local-against-remote run recipe; recorded the 2026-06-14 sweep.

## Live action taken

```
cleanup_inbox_courses --include-ownerless --dry-run   # showed inbox-7
cleanup_inbox_courses --include-ownerless             # deleted it
```

Post-fix verification on the live DB: **0 `Inbox` courses remain**
(3 courses total, down from 4). The cascade also removed the orphan's
single subscription, so the duplicate Inbox no longer appears for that
user.

## Verification

- `courses` test suite: 7/7 pass under `settings_test`.
- Live DB: re-queried `Course.objects.filter(title__iexact='inbox')`
  → 0 rows.
