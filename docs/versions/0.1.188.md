# 0.1.188 - Imported-course reading order + bind pending-state fix

Two tracked bugs from the backlog (GitHub Issues was empty — see the
issue-migration note below).

## Imported courses now read top-to-bottom

Imported notes had no ordering field, and the course view listed notes
by `-last_edit`. Every note of a git-import is written within the same
second, so the "order" users saw was effectively arbitrary (and often
reversed) — Veronica-7's 193 notes never read in their document order.

- **`Note.sort_order`** (migration `0022`, indexed): reading position
  within the course, set on git-import as
  `(module_index + 1) * 1000 + note_index + 1` so modules stay grouped
  and in order while notes keep the adapter's within-module order
  (frontmatter `order`/`sidebar_position`, then path).
- `CourseNotesApiView` orders by `("sort_order", "-last_edit")`.
  Natively-created notes keep `sort_order = 0`, so they still fall back
  to pure recency — **existing behaviour unchanged** for non-imported
  courses (covered by a test).
- Re-import updates the position (it participates in the change check),
  so fixing order in the repo propagates.

## Binding without sync no longer reports "pending"

`apply_course_git_binding` armed `git_pending_since` whenever a repo was
set, even with `sync_enabled=false`. Harmless mechanically
(`flush_due_course_syncs` filters on `git_sync_enabled`) but the git
payload advertised a permanently pending sync, which reads as stuck.
Now the debounce is armed only when sync is actually enabled, and
cleared when it is turned off.
