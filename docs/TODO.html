Investigation path (editor_app/lib/app_shell.dart): _parseNoteUuidFromUrl reads the fragment after #; _bootstrapApp calls _openNoteByUuid AFTER _loadInitialData. Possible causes: (a) the URL fragment regex is case-insensitive but may not match when the shared link carries a trailing slash or query string; (b) _handleOAuthCallback already does browserReplaceState and strips the fragment when handling ?code= / ?state= — check if it's stripping the note fragment before the deep-link parser runs; (c) for a private note opened without a session, the UUID endpoint returns 403 but the error message is just stuffed into _errorMessage without a clear "sign in to view" prompt.
